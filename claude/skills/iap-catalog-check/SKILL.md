# 内购目录怎么核对

## 何时用

- 新充值档/礼包上架前
- 商店展示与实发权益不一致
- 重复档或价格倒挂
- 活动礼包冲击常驻目录

## 怎么做

### 1. 建目录主表

1. 每条写：SKU ID、平台商品 ID、价格档、货币、是否订阅、上下架状态、展示位。
2. 对齐商店后台与客户端配置主键；一侧缺失标断裂并分「缺后台/缺客户端」。
3. 声明范围：常驻/活动/订阅；活动写起止与到期处理；订阅写续费与取消入口字段。
4. 活动 SKU 与常驻分栏；与 liveops-calendar 窗交叉，避免无声重叠。
5. 涉及产品表时走表沙盒编辑；晋升另开表 diff。
6. 不合格：主键断裂或范围字段空 → 回本步补齐再核权益。

**做到**：主表 SKU/平台 ID/价格档齐全；断裂已分缺后台/缺客户端；活动窗与日历交叉。

### 2. 核对权益与展示

1. 每 SKU 列权益：物品/货币/时长；对照直发或邮件通道字段。
2. 展示卖点数字必须在实发列表找到对应项；限时/首充/返利写成给定/当/则。
3. 同内容不同 SKU 标出并给合并/差异化选项。
4. 实发走邮件时与 reward-mail-check 通道 ID 对齐。
5. 内容物 id 须在物品表真实存在；幽灵 id 标红。
6. 不合格：展示与实发不一致 → 回改正文案或权益列。

**做到**：展示数字均可在实发权益核对；邮件通道与 reward-mail 对齐；幽灵 id 已标红。

### 3. 扫描价格与档位问题

1. 查价格倒挂、重复档、相对单买不可解释的「假折扣」。
2. 限购与刷新含时区；通行证周期对齐赛季重置点。
3. 与 monetization-kpi-pass 禁区交叉：碰战斗公平的条目升决策。
4. 价值可解释句写入目录备注；无解释不进可上架集。
5. 沙盒购发退路径列入检查：购买成功/取消/到账失败。
6. 不合格：倒挂或禁区未裁 → 回改档位或升级决策。

**做到**：无未处理倒挂；限购刷新含时区；通行证对齐赛季；沙盒购发退路径已列。

### 4. 收口可上架集

1. 输出可上架集 + 阻断清单 + SKU↔商店 ID 对照表。
2. 埋点事件名清单给分析/程序；拉不出事件则阻塞上架。
3. 回滚与下架执行人、配置版本写入文档仓。
4. 命名与商店展示约束过 copy-pass 短句。
5. 版本标签冻结后改价须记影响面（经济/活动/KPI）。
6. 不合格：对照表缺行或埋点缺失 → 回步骤 1/3 补齐。

**做到**：可上架集+阻断清单+SKU↔商店 ID 对照入文档仓；埋点事件名齐全。

## 做到

- SKU 与平台/客户端 ID 对照无断裂
- 展示数字均可在实发权益中核对
- 价格档无未处理倒挂；限购刷新含时区
- 可上架集与阻断清单已入文档仓

## 失败回哪一步

- 步骤1（建目录主表）：主键断裂或范围字段空 → 回本步补齐再核权益。
- 步骤2（核对权益与展示）：展示与实发不一致 → 回改正文案或权益列。
- 步骤3（扫描价格与档位问题）：倒挂或禁区未裁 → 回改档位或升级决策。
- 步骤4（收口可上架集）：对照表缺行或埋点缺失 → 回步骤 1/3 补齐。

下一步常接：`monetization-kpi-pass`；`monetization-designer`；`liveops-calendar`；`reward-mail-check`；`copy-pass`。
