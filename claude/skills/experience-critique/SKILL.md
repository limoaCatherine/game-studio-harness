# 体验怎么批评

## 何时用

- 试玩/垂直切片后要结构化批评；反馈散乱需归因到层
- 「好不好」缺支柱参照；改版前要定修复优先级
- 需把主观感受落成可验证观察（录像点/埋点/计时）

## 怎么做

### 1. 收集可复核观察（录像/时间码）

**做**
1. 记录本轮构建号/SHA、平台、画质档、试玩日期；工具面=`git rev-parse --short HEAD` 或构建面板截图，写入批评包头。
2. 开 OBS / 引擎 Movie Capture / 设备录屏；每段试玩保留原始文件路径到 `playtests/<date>_<sha>/`。
3. 每条反馈改写为观察句：情境 + 玩家行为 + 可观察结果；纯形容词（烂/妙）逼问成观察或删除。
4. 绑定支柱 ID（读 `game-pillars.md`）或标「支柱外」；合并同因观察并记出现次数——票数不自动抬严重度。
5. 可复现项写编号步骤或录像 **时间码**；偶发写触发条件并降权。无复现步骤不得升阻断。
6. 对照 `pacing-pass` 异常 csv 与 `combat-feel-checklist`：标「已预知 / 新发现」。
7. 向用户确认本里程碑成功证据句；严重度必须对齐该证据，不对齐则降级。
8. 失败→回本步：无构建号，或观察无时间码/步骤——补证据包后再进入归因。

**做到**：批评包头含 sha+平台；观察表每行有支柱内外标记；可复现项 100% 有步骤或时间码。

### 2. 归因到层 + 埋点/日志对照

**做**
1. 归因层枚举：流程关卡 / 数值 / 手感表现 / 信息 UI / 叙事 / 活服节奏 / 技术性能。
2. 拉对照信号：死亡/卡关漏斗埋点、`Player.log`/Crashlytics、Unity Profiler / Unreal Insights 尖峰帧号、UI 点击热区——写入「若归因为真应看到」。
3. 严重度三级：阻断支柱或里程碑证据 / 损伤 / 毛刺；只对齐当前里程碑，不拿远期幻想抬级。
4. 错层检查：疑似用数值治 UI、用加怪治节奏真空——标错层并改归因层。
5. 性能/崩溃阻塞试玩→标技术阻断，建缺陷单并分流 `client-bugfix`，不在体验层空转。
6. 叙事失调（故事奖励 vs 玩法奖励反向）挂回 `narrative-beat-sheet` ludonarrative 项。
7. 失败→回步骤 1：假设写不出否证信号（无埋点名/无帧号/无时间码）——降为猜测，移出阻断队列。

**做到**：每条有层+严重度；阻断级有否证信号槽（埋点名或帧号或时间码）；技术阻断已分流单号。

### 3. 保砍改批注

**做**
1. 每条批注指向具体物件/规则/镜头/UI 控件（可检索 id 或路径），禁止「再打磨」空话。
2. 批注格式落主路径：`obj_ref | pillar_id | 保/砍/改 | 建议动作 | evidence | Owner`。
3. 与支柱打架的功能给一句替换幻想方向；未达标项汇总给制作跟进。
4. 严重度对齐本里程碑成功证据；美化池与阻断分栏，美化不得挤占阻断产能除非用户重排。
5. 分流指针写入：手感/节奏/UI/活服等到对应事件 skill id，做法读事件文件。
6. 失败→回步骤 2：批注无法指派 Owner 或无否证信号——先补归因再批。

**做到**：批注表可按物件检索；每条有保/砍/改+Owner；阻断与美化分栏。

### 4. 交付批评包

**做**
1. 一页事实摘要给制作人/CD：构建号、阻断数、保砍改计数。
2. 登记批评包路径与录像索引；未关闭项进下一切片继承。
3. 修复后在同平台相近构建按验证点复验；关闭必须附新时间码或埋点证据。
4. 产能溢出当场触发 `scope-cut-decision` 或降毛刺；常接 `pillar-define` 复审。
5. 失败→回步骤 3：关闭无证据则重开批注卡。

**做到**：批评包含构建号、观察表、保砍改批注；阻断项均有复现步骤或时间码。

下一步常接：`scope-cut-decision`；`pillar-define`；`feature-gdd-slice`。
