# UI 逻辑怎么定

## 何时用

- 屏交互要可接线实现，按钮与数据不同步或重复提交
- 错误码无用户态映射，要给程序的逻辑表
- 竞态、回前台刷新、乐观更新回滚未定义
- 玩法规则疑似藏在 UI 分支里

## 怎么做

### 1. 画状态机与防重

1. 列本屏状态集（空闲/加载/成功/错误/权限不足/空数据等）与转换表；非法转换写拒绝策略。
2. 加载中禁用可点控件；防重复提交（锁时长或幂等键）；离开屏清锁规则。
3. 与 ux-flow-spec 步骤 ID 对齐；对不上补态或改流程。
4. 回前台/重连：哪些请求重放、哪些只刷新；避免双下单。
5. 模态/叠层：关闭序与返回键；下层热区不可点穿。
6. 高代价事件幂等与对账策略向制作方确认。
7. 不合格：态与流程步骤对不上 → 回改映射。

**做到**：合法转换表与防重规则齐全；与 ux-flow 步骤 ID 对齐。

### 2. 事件与数据绑定

1. 写输入事件→动作→请求/本地事件；数据来源与刷新时机（进屏/回前台/推送）。
2. 字段名与契约对齐；失败码映射到错误态与文案键（copy-pass）。
3. 乐观更新须写失败回滚字段列表；回滚后提示用户。
4. 列表/分页：空、末页、超时、失败重试、占位骨架。
5. 红点：计算来源、已读清除、跨屏一致。
6. 埋点成对事件名（进入/成功/失败），不记 PII；与流程事件槽同名。
7. 不合格：失败无态可去或回滚字段空 → 回补。

**做到**：事件/字段/失败码可接线；乐观更新回滚字段显式；埋点成对。

### 3. 错误、竞态与规则边界

1. 错误分层：可重试/需离开/需客服；各层文案键与按钮集。
2. 竞态：连点、慢网、重复回调；用锁与序列号策略写清。
3. 禁止把玩法规则藏在 UI 分支；规则归属系统 GDD，UI 只反映状态。
4. 权限不足与未登录态入口；深链补前置。
5. 与商店/邮件等高代价屏交叉幂等会签。
6. 不合格：规则藏 UI 或竞态未定义 → 回流系统或回步骤 1。

**做到**：错误分层与竞态策略写清；玩法规则不藏 UI。

### 4. 交付逻辑表

1. 输出：状态转换表、事件绑定表、错误码映射、幂等说明、埋点清单。
2. 节点/屏 ID 稳定供程序引用；版本号写入文档仓。
3. 验收：主路径点通、重复提交不双单、断网恢复不丢主路径。
4. 与 ux-review 问题单交叉闭阻塞。
5. 变更影响面：谁依赖旧态名。
6. 不合格：程序需猜事件名 → 回补表再交。

**做到**：逻辑表（状态转换/事件绑定/错误码/幂等/埋点）可交程序；主路径与断网恢复可指。

## 做到

- 合法转换表与防重规则齐全
- 事件/字段/失败码可接线；回滚字段显式
- 埋点成对且与流程槽同名
- 主路径与断网恢复验收记录可指

## 失败回哪一步

- 步骤1（画状态机与防重）：态与流程步骤对不上 → 回改映射。
- 步骤2（事件与数据绑定）：失败无态可去或回滚字段空 → 回补。
- 步骤3（错误、竞态与规则边界）：规则藏 UI 或竞态未定义 → 回流系统或回步骤 1。
- 步骤4（交付逻辑表）：程序需猜事件名 → 回补表再交。

下一步常接：`ux-flow-spec`；`ux-review-pass`；`copy-pass`；`ux-designer`。
