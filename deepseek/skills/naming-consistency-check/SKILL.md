# 命名怎么统一

## 何时用

- 同义多名或一名多义，表字段与 UI 键不一致
- 重构前要评估改名扇出
- 本地化键失控，中英混用无规则
- 文案/程序/数值对同一概念各叫各的

## 怎么做

### 1. 定范围、权威源与命名规则

1. 锁定扫描范围：系统名、表主键/字段、UI 键、可见代码符号、对白说话人 id、关卡/任务 id。
2. 定权威源优先级（术语表 > GDD > 登记表 > 散落文案——以用户项目为准）；无权威源先建最小术语表再定品味。
3. 写本项目命名规则摘要：大小写、分隔符、单复数、中英是否并存、显示名与稳定键是否分离。
4. 向用户确认「键少改、显示名可改」是否为现行政策；不是则写明例外域。
5. 列出本轮必扫目录/表名；超出范围记指针。
6. 准备检索手段：全文搜、表头导出、字符串表导出；缺工具则手工抽样并声明覆盖率。

**做到**：扫描范围路径、权威优先级、规则摘要、键/显示名政策、覆盖手段写成可执行清单。

### 2. 冲突扫描

1. 扫：同义多名、一名多义、大小写/单复数漂移、中英混用无规则、过时前缀残留。
2. 每条记：概念一句话、现用名们、出现位置（文件/表/键）、问题类型、权威候选。
3. 估扇出：每个改名候选的引用约数（高/中/低）；高扇出标「必须整包替换」。
4. 检查稳定键是否被当显示名改来改去；若有，拆成 key + display 两列建议。
5. 检查任务/对白/关卡 id 是否与显示标题耦合；耦合则建议解耦，防改标题炸存档。
6. 与 `copy-pass` 弃用清单合并，避免两套替换表。

**做到**：冲突清单可按 token 检索；类型与扇出已标；键/显示名问题分栏显式。

### 3. 统一方案与替换序

1. 定规范名 + 弃用名列表；建「概念→规范名→弃用名→稳定键」对照。
2. 写替换序：登记/术语表 → GDD → 数据表 → UI 键 → 对白/任务文本 → 代码符号；高扇出整包计划，按序一起改。
3. 给用户 2 套争议名选项及检索命中数，选定后冻结本批决议版本。
4. 输出弃用名检索清单供自清；CI/手工复查勾选「零命中」或「已知残留路径」。
5. 产品表改名走表格写入配方（`excel-com-write`）+ `tunable-table-diff`；主键变更附存档/迁移说明。
6. 存档/网络协议中的字段改名：写迁移策略或「本版只改显示」——成本写进决议。

**做到**：决议表含保留名/废弃名/替换计划；高扇出有替换步骤；迁移与只改显示策略清楚。

### 4. 验证与冻结

1. 跑弃用名检索；残留按阻塞/可延后分类，可延后必须无玩家可见。
2. 抽 10 个高频概念：UI、表、任务文本三处是否同名；不一致回修。
3. 更新术语表「决议日期/版本」；通知文案与程序 Owner。
4. 新概念入库检查单：无规范名先补名再进表头；本检查单交团队沿用。
5. 记录本轮未扫范围，防「已全库统一」幻觉。
6. 对本地化已译键：改规范显示名时同步开 L10n 失效清单，避免旧译残留与新名并存。

**做到**：残留可接受或清零；三处抽检一致；术语表版本更新；未扫范围诚实列出。

## 做到

- 冲突清单覆盖约定范围；权威源明确，规则摘要可查
- 规范名与弃用名已定；替换序可执行，高扇出有计划
- 弃用检索清零或挂账无玩家可见残留；键/显示名与存档迁移策略清楚

## 失败回哪一步

- 范围空、无权威源、规则摘要糊 → 回步骤 1
- 冲突未分类型/扇出、键显示名未拆 → 回步骤 1 补规则后重扫步骤 2
- 高扇出只改一处、静默改主键 → 回步骤 2 重估扇出，按步骤 3 整包替换
- 残留玩家可见、三处不一致 → 回步骤 3 执行替换后重跑步骤 4

下一步常接：文案 `copy-pass`；表变更 `tunable-table-diff`。
