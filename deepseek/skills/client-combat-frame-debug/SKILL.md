# 客户端战斗帧怎么调

## 何时用

- 出手与特效/受击闪不对齐
- 判定窗偏早偏晚难调
- 事件帧漂移，需逐帧看见窗口
- 网络延迟下补偿显示不可信

## 怎么做

### 1. 建共用时间线

1. 选问题技能，在表格或调试视图拉同一时间轴：动画 notify、判定开关、VFX spawn、受击反馈。
2. 标权威事件（只显示服务器结果）vs 本地预测；记下当前帧号来源（动画时间 vs 逻辑帧）。
3. 导出或截取 AnimEvent/Notify 列表与技能配置表中的帧/秒字段；全部换算为「帧@逻辑帧率」再比。
4. 记下打断/取消/被控时窗口是否提前关闭的设计期望；多段技能分段建子时间线。
5. 产出一页时间线：四类事件可对齐比较，含帧号列；表写入走 `excel-com-write` 若项目用 xlsx。

**做到**：一张时间线含 AnimEvent/判定窗/VFX/受击闪四类+帧号列；单位帧/秒已统一。

### 2. 开调试 HUD

1. 显示当前帧、事件触发瞬间高亮、判定开/关、延迟补偿值（若有）；HUD 用开发命令或宏，只进 Debug/Profile 构建。
2. 用引擎慢放/逐帧（或录制后逐帧看）量出偏早或偏晚的具体帧差；量帧差时固定机器帧率上限，防动态帧率干扰。
3. 对照 Profiler/自定义 Marker：技能开始、Hit、VFX、Hurt 的时间戳差。
4. 多机或录屏时叠加帧号烧录，便于对比。
5. 把「早/晚 N 帧」写入问题单；偏差用帧差数字表达。

**做到**：偏差能量化到「早/晚 N 帧」；HUD/Profiler 尖峰帧号有记录。

### 3. 只修表现对齐

1. 调事件帧、VFX 挂点或动画；权威结算数字保持不变（伤害/命中结果走 `server-combat-authority-check`）。
2. 改配置表帧字段时同步 AnimEvent，防双源漂移；改 AnimNotify 后重导出核对表帧是否仍旧。
3. 打断/取消/被控路径重走一遍，确认窗口仍合理。
4. 预测失败和解时：表现回滚或校正是否视觉可接受；录一段前后对比视频。
5. 改动打标签 COMBAT_FEEL 便于回归检索。

**做到**：听看打一致；权威结算数值未改；打断路径已测。

### 4. 技能子集回归

1. 子集至少含：本技能、同模板邻技、一技能打断用例；记前后帧差。
2. 网络延迟下抽测补偿显示是否仍可信（开项目网络工具，写延迟 ms）。
3. 检查共用模板的其他技能是否被带偏。
4. 残留问题分类：仍偏帧 / 模板缺陷 / 引擎事件不准。
5. 把通过的技能与帧差记录进战斗手感回归清单。

**做到**：回归子集有通过/失败结果；邻接技能已扫。

## 做到

- 时间线含 anim/判定/VFX/受击且单位统一
- HUD 能量化帧差；表现对齐且权威数未改
- 打断/取消路径测过；子集回归有记录

## 失败回哪一步

- 时间线缺列、帧/秒未统一、多段未分子时间线 → 回步骤 1
- 帧差能量化不了、HUD 进了 Release、动态帧率干扰采样 → 回步骤 2
- 改了权威结算数、Notify 与表双源漂移、打断路径未测 → 回步骤 3
- 邻技/打断未回归、延迟补偿未抽测 → 回步骤 4（必要时回 3 重采对齐）

下一步常接：`anim-event-hook`；权威面 `server-combat-authority-check`。
