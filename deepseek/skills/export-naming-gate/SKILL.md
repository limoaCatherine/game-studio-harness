# 导出命名扫描与改名

## 何时用

- 导出前要批量扫命名
- 外包回传 token/后缀漂移
- LOD/变体后缀多种并存
- 改名后 Prefab/表引用断裂

## 怎么做

### 1. 锁定命名规则

1. 打开项目 NAMING/Asset Standards：抄下 Domain、Type、Name、Variant、LOD token 顺序；贴图后缀表；大小写与分隔符约定。
2. 圈定本批扫描根目录与白名单前缀；根路径写进任务备注，范围可复述。
3. 例外清单：每条写路径模式、理由、到期条件；新例外必须带到期日。
4. 与 `export-pipeline-fix`/校验脚本使用同一规则版本号；规则改了要升版本再扫。
5. 向用户确认本批是否含动画、贴图、网格；缺规则的类型先补规则再扫，不混用另一品类规则。
6. 备好期望正则或 glob 示例（各 Domain 一条），用于人工抽查脚本是否误报。

**做到**：规则版本与扫描根可复述；例外有到期。

### 2. 扫描违规与断引用

1. 用脚本或 glob 扫导出根；每条记：当前路径、期望模式、问题类型（空格/中文/缺 token/Domain 漂/后缀混用）、建议名。
2. 分阻塞与可延后：空格、中文、缺 Domain/Type、LOD 后缀多种并存→阻塞；纯大小写且引用未断→可标延后但须条件。
3. 同步扫引用面：代码、Prefab/蓝图、数值表、动画状态机仍指向旧名；标 Missing（引用在文件无）与 Orphan 候选（文件在无引用）。
4. 贴图额外记：非 POT、超档位尺寸、错误容器；尺寸档向用户索取。
5. LOD/变体：统一一种后缀写法（LOD1 vs _lod1），列出并存样式并定保留式。
6. 输出违规表按路径排序，阻塞置顶；同一资产多问题拆多行便于勾选。

**做到**：违规表按路径可勾；Missing/Orphan 分开；LOD 后缀冲突可见。

### 3. 改名并修引用

1. 可脚本则按建议名批量改；先 dry-run 出 diff，确认无误伤白名单外文件。
2. 同步改材质槽贴图路径、Prefab 引用、动画片段路径、表字段；改完导入引擎看 Missing 是否清零——文件名与引用一起改。
3. 修复顺序：阻塞命名→Missing 断引用→Orphan（删除必须人工确认，默认只候选）。
4. 外包包回传对照表（旧名→新名），避免下一包又漂回旧名。
5. 改名后抽查 1～2 个关键 Prefab/场景：引用是否绿、Console 无 Missing。
6. 无法自动改的二进制引用：列手动清单与责任人，未完成前不宣称本批清零。

**做到**：改名项引用已同步；Orphan 仅候选未误删。

### 4. 同规则重扫

1. 同一规则版本、同一根目录重扫；对比新旧违规数，每条「消失」须能解释已改/已移出根。
2. 阻塞项清零才交给 `import-validate`；剩余延后项写清条件与到期。
3. 把本批规则版本+扫描根+结果摘要写入任务备注，供 CI/管线复用。
4. 若规则本身误报：修规则并升版本再重扫；保留真实结果，不手工删行装绿。
5. 抽查建议名是否仍命中正则；抽查失败则修生成器。
6. 打开命名扫描日志确认无未分类错误行残留。

**做到**：阻塞=0 或延后条件显式；可进导入验。

## 做到

- 规则版本与扫描根明确；约定目录扫完；阻塞违规已改或条件延后
- 改名项的 Prefab/表/材质引用已同步；Missing 优先处理
- 重扫阻塞清零；LOD/变体后缀统一

## 失败回哪一步

- 规则版本空、扫描根口头无范围、例外无到期 → 回步骤 1
- 违规表空但肉眼有问题、Missing/Orphan 未分 → 回步骤 2
- 只改文件名引用仍断、Orphan 误删 → 回步骤 3
- 重扫仍红、误报装绿 → 回步骤 4（规则误报则升版本回 1）

下一步常接：`import-validate`。
## 加厚：公开管线命名契约（可执行）

### A. 通用 token 表（对照项目版，勿照抄商业前缀当唯一真理）

1. 网格类常见可观察前缀族：静态网格、蒙皮网格、碰撞体（凸包/盒/球）——以项目 Asset Standards 为准；碰撞体名必须能与渲染网格名一一对应（同名核+前缀差异）。
2. LOD 后缀只保留一种风格：`_LOD0/_LOD1/...` 或 `LOD0` 嵌入位，禁止同批并存 `_lod1`/`LOD1`/`_L1`；扫描脚本对并存样式一律标阻塞。
3. 贴图后缀表至少覆盖：漫反射/颜色、法线、遮罩/金属粗糙、自发光、AO；通道与色彩空间（sRGB vs 线性）写在同一张表，导入预设按表勾。
4. 动画片段：一动作一文件优先；文件名含 `Domain_Type_AnimName[_Variant]`，不把多个 take 隐式堆进同一导出却不写 take 清单。
5. 变体 token（破损、换装、季节）固定位置：Name 后、LOD 前；位置漂了视为 Domain 规则违规。
6. 大小写与分隔符：全项目统一 `_` 或 Camel；空格、全角、连续双下划线一律阻塞。

**检查信号**：命名扫描日志里「并存后缀样式数=0」；抽 3 个资产人工复述 token 顺序一致。

### B. 改名联动面（防止只改磁盘名）

1. 材质槽贴图路径、预制体/关卡引用、动画状态机片段路径、数值表资源字段四类必须同批改或进手动清单。
2. dry-run 输出：旧路径 → 新路径 → 引用命中数；命中数=0 的改名项标「可疑孤儿改名」人工确认。
3. 引擎内打开 1 个主角预制体 + 1 个关卡：Console Missing=0 才算本批改名绿。
4. 外包对照表（旧→新）随包发出；下一包扫描若再现旧名，记「回漂」并升级为例外到期问题。
5. 规则版本号写入扫描报告文件名或页眉；CI 复用同一版本，禁止口头「还是那套规则」。

**不合格回**：规则不清 → 步骤1；只改文件名 → 步骤3；重扫仍红 → 步骤4。

## 工具锚点（live mcp.json）

- `everything-search`：扫导出根与引用面
- `gamedev-mcp`：改名后 Missing 扫描
- `excelMCP`：违规表/旧→新对照
- `roslyn-mcp`：若命名扫描器是 C#（可选）
- **DoD：** 阻塞命名=0；引用同步；重扫绿。
