# Game Studio Harness

游戏制作代理缺的不是更多技能文件。缺的是：窗口里装得下这一件、正式面不被试错毁掉、换窗口之后还能接着做。

本仓用封版的四层来管这三件事。它不附带引擎或 DCC。它附带的是一种编排：谁来选上下文、谁来做事、谁来碰正式文件。

## 专注度

大模型的窗口是稀缺的。一条游戏制作流水线从支柱走到发版，做法可以有一百份；把它们同时塞进上下文，代理看起来很全能，实际在串岗、抢写、丢掉本轮边界。

我们不靠提示词里的「请专注」。**第二层对第三层握手**：先选职种或事件，再从能力库里只取这一轮用得上的切片。职种是路径，不是清单——点一条岗，先看第一步，走到哪一步再打开哪一份做法。外接同样：开场只握必须握的手，其余用到再拉。

这样合理，是因为「相关性」一旦交给模型自己猜，它会为了保险把可能用到的全部打开。握手把相关性收成一个集合。集合小，专注度才可预期。

## 四层为什么不能合成三层

宪法必须每轮都在，所以必须薄。做法必须可复用，所以必须厚。这两件事不能写在同一层：写在一起，要么宪法被做法撑破窗口，要么做法被剪成口号。

定档也不能并进能力库。库回答「这件事怎么做」；导演回答「这一轮点谁」。没有导演，库会自己当导演，每轮读完全部技能。

档案柜也不能并进前三层。会话会断。进度、正式面、已批准事实如果只活在聊天里，下一手只能重猜。档案柜承认自己不会推理：只记做到哪、正式面在哪、哪句已经批准。口头想法要进库，须人准。

五套编程工具（Cursor、Claude Code、Codex、Grok、DeepSeek）是同一套四层的五份齐套拷贝，不是第五层。落点会变，运转法不该变。

## 任务编排

定档 → 制作 → 结案，不是项目管理套话。它解决的是代理会同时做三件有害的事：把可能相关的做法都打开、同时扮演几个岗位、直接改看得到的正式文件。

一件交付一个会话。口径变了，先改合同再换上下文，不沿旧集合把上一稿做完。另一件插进来，旧件停在旧会话里，不关、不混。岗位职责不同，就按职种分开做——专注度的边界是岗位，不是「请你同时当数值策划和客户端」。试错默认进隔离根；正式面只在人准的那一下，按记录集回写。

这样合理，是因为编排的对象不是任务看板，是**上下文集合和写权限**。集合稳，代理才不会在转向时带着过期技能说话；写权限收住，并行会话才不会互相覆盖正式面。

## 技能、子代理、外接怎样托住制作

三种东西粒度不同，不能合成一种。

**技能**是一件事的做法：定支柱、写伤害公式、过导入校验、出验证结论。当次数字和当次路径不准写进技能。技能在库里，被点名才进窗口。

**子代理（职种）**是一条岗的走法。战斗数值策划从建模走到晋升，关卡策划从目标链走到节奏，测试负责人从计划走到豁免。同一诉求里岗位不同，优先各开一只，主会话只负责点名和收口。一只代理又改表又写客户端又验收，不是效率，是串岗。

**外接**是宿主的手：改表、进引擎、动 DCC、画图。软件可以不在，架构仍应能转。三十六条外接若开场全连，发现阶段会被空等吃掉；所以默认只让每日要握的手直连，其余懒接。

制作流水线被托住的方式，是每一段都有岗可点、有技能可按步打开、有手可以伸向对应软件：

![制作流水线](figures/制作流水线.svg)

方向一段，职种是创意总监，技能是支柱、体验批注、砍范围。规则与数值一段，系统策划、战斗策划、三路数值策划各走各的路径，改表的手是表格外接。体验与资产一段，叙事、交互、关卡、原画、绑定、动画、特效、技美、音频各有岗；建模、地形、Bank 这类事伸向对应 DCC。工程与验收一段，客户端、服务端、工具、测试分开，引擎和代码外接按需出现。运营一段，活服、商业化、发版说明接到日历、活动规格和商店目录。

流水线长，所以更不能把整条灌进一轮。第二层每次只握住其中一段。

## 装到本机

Windows，Python 3.11+。双击 `一键部署.bat`，填写业务根。本包装架构，不装宿主软件；已有的外接配置不会被覆盖。

探测（不写真实用户目录）：

```powershell
python install/install.py --isolate-root D:\probe --workspace D:\probe\ws --tools all
python install/verify_install.py --isolate-root D:\probe --workspace D:\probe\ws
```
