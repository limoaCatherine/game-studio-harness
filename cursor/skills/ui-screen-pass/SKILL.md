# UI 单屏怎么落

## 何时用

- 流程步要落成可实现单屏
- 布局层级乱、主操作不突出；缺空/加载/错误/满数据态
- 未引用 Kit、切图/token 未齐

## 怎么做

### 1. 对齐流程与信息层级

1. 对照用户流程节点确认本屏输入/输出与成功失败出口。
2. 信息层级：标题、主操作、次操作、状态反馈、法律/次要链接分区。
3. **空态 / 加载 / 错误 / 满数据** 四态列表先写再画。
4. 与 Kit 合同核对可用控件；缺件先提 `ui-kit-spec` 再开特例。
5. 安全区与多分辨率适配框定。
6. 文案占位与最终文案责任分界标清。

**做到**：四态列表在；屏职责与主操作可指；Kit 缺件已提申请。

### 2. 铺布局并引用 Kit

1. 线框到高保真只使用 Kit 变体×尺寸×状态；每控件写 `kit_id`。
2. 主按钮唯一视觉焦点；危险操作二次确认态画出。
3. 列表/网格大量条目用分页或虚表示意。
4. 红线标注间距 token，不写随意像素；与风格锚色板一致。
5. **切图清单**：名、尺寸、九宫、引用控件（自动或手列）。
6. 多分辨率：折叠/滚动/断点规则写明并做 min/max 预览。

**做到**：控件均有合法 kit_id 或已批特例；切图清单可指；token 引用完整。

### 3. 多态跳转与交互说明

1. 为四态各出关键帧；状态切换箭头可指。
2. 跳转目标屏 ID 与返回栈行为写清（跳转表）。
3. 短动效仅定时长与缓动类别；埋点/播报只列事件名。
4. 键鼠/手柄/触控焦点顺序若需要则附表。
5. 交互说明一页内可开发读懂。
6. 未完成四态不得标屏完成。

**做到**：四态齐全且跳转表可指。

### 4. 验收交接开发

1. 对照流程走查：主路径与失败路径可点通。
2. Kit 外特例列表须有批准。
3. 交付：屏稿、切图清单、状态表、跳转表、字体色 token 引用。
4. 开发预览对照差异表；超差回本 pass。
5. 通知 `ui-artist` / 客户端 UI 工程。
6. 可达性快检：主路径焦点可走；对比度抽检关键文本。

**做到**：主失败路径走查通过；交付包字段齐，可交开发。

## 做到

- [ ] 四态齐全且跳转表可指
- [ ] 控件均引用 Kit 合同或已批特例
- [ ] 切图清单与 token 引用完整
- [ ] 主失败路径走查通过并可交开发

## 工具锚

- UI 预制 / 蓝图路径（`Assets/` 或 `Content/`）
- 流程说明可用 `xmind` 或稿件 `.md`；交互状态表 `.xlsx`
- 真机截图落入 `.harness/artifacts/`

## 失败回哪一步

- 流程出口不清、四态未列 → 回 1
- kit_id 未知、切图/token 空 → 回 2（缺件先 `ui-kit-spec`）
- 缺态、悬空跳转 → 回 3
- 走查不通、特例未批 → 回 3/4

下一步常接：实现；文案可交文案技能。不重定义 Kit 基础控件长文。

工具锚：设计稿工具 · UI Kit 合同表 · 切图命名规范表 · 引擎 UI 预览 · 流程说明
