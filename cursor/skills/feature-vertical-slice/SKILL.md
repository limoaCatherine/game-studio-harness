# 功能竖切怎么落地

## 何时用

- 要证明管线/架构/乐趣是否还在
- 跨端契约需先冻一小环可玩
- 范围膨胀，需砍到可演示
- 演示前缺失败态与日志

## 怎么做

### 1. 定验证问题与范围

1. 写本切片要回答的一类主问题（管线通 / 架构扛得住 / 乐趣还在），写成可证伪句。
2. 圈 start→challenge→resolution 最小系统集；目标 3–5 分钟可玩。
3. 写含/不含清单各至少 3 行；不含系统用桩，但演示不得把玩家看不见的作弊当乐趣证据。
4. 估工期：1–3 周做不完则重切；定硬时限与沉没成本检查点（第 N 天整环仍不可演示则停）。
5. 分支/目录标记 VERTICAL SLICE + 验证问题 + 日期，防误合生产。

**做到**：验证问题一句可判定真假；含/不含与时限写死。

**不合格**：验证问题空或范围回潮无不含清单 → 回本步改边界。

### 2. 计划可观察成功标准

1. 成功标准写成可观察证据：完成一局、失败提示可见、日志事件名。
2. 失败态最低集至少 2 条；跨端冻结点写最小协议字段、最小存档键、错误码。
3. 写演示脚本草稿：步、操作、期望、日志点；文件头标验证问题与日期。
4. 品质线可占位，但须有代表性；契约/存档最小集指针写入切片卡。

**做到**：成功标准可演示判定；失败态与冻结点显式。

**不合格**：成功标准不可演示判定 → 回步骤 1 改问题或标准。

### 3. 实现主路径与失败态

1. 实现顺序：先主路径可构建可点，再失败态可读，再日志打点；数值进配置。
2. 关键失败态：超时/拒绝/空数据/存档失败等提示可读；状态落点单一避免双写。
3. 每日用同一演示脚本跑；整环不可演示则停加重切或翻假设，不堆范围。
4. 切片代码目录或条件编译与生产隔离；权威数字问题单独立项。

**做到**：整环可演示；约定失败态覆盖；关键日志键可追踪。

**不合格**：只通主路径无失败态/无日志键 → 回步骤 2 补标准后重做本步。

### 4. 试玩并裁决

1. 至少一轮试玩；对照验证问题逐条给证据（录像时间码/日志）；记卡点与技术风险。
2. 裁决：`PROCEED` / `PIVOT` / `STOP` + 依据；PIVOT 写下刀范围，STOP 写学到什么。
3. PROCEED 必须附「还缺什么才能进生产」；新想法进 backlog 不当场膨胀。
4. 速度日志（何日打通何段）与材料路径写入报告。

**做到**：试玩裁决枚举成立且附证据；PROCEED 含生产缺口清单。

**不合格**：无证据口头通过 → 回本步补试玩证据。

## 做到

- 验证问题可判定真假；含/不含与时限写死
- 整环可演示；约定失败态覆盖；关键日志键可追踪
- 试玩裁决枚举成立且附证据；PROCEED 含生产缺口清单

## 工具锚

- 里程碑与范围裁切记录 `.md`
- 会话 `loadplan.json` / `activated.json` 与 `~/.cursor/skills` / `agents` / `mcp.json` 点名对照
- 发版说明与 `sync-state` 状态摘要路径

## 失败回哪一步

- 验证问题空、范围回潮 → 回步骤 1
- 成功标准不可演示 → 回步骤 1/2
- 只通主路径无失败态/无日志键 → 回步骤 2 后重做步骤 3
- 无证据口头通过 → 回步骤 4
