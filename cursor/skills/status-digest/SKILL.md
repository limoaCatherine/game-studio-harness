# 状态摘要怎么写

## 何时用

- 日会/周报需要一页事实进度，不是形容词叙事
- 交付包阻塞要汇总给制作圈，含升级时限
- 与 `sync-state` 对齐单一事实源后再分发

## 怎么做

### 1. 采事实源

**做**
1. 对齐工作项板、交付包 id、会话卡、产物索引为单一事实源；多频道各写各的先停，指针 `sync-state`。
2. 只采可复核字段：完成/进行/阻塞、证据路径、Owner；缺席 Owner 的包当日标红。
3. 起稿三行计数器：红灯数、需决策数、关键路径健康（健康/亚健康/红）。
4. 风险台账高项只取指针一条，不在此重写方法论。
5. 禁止把形容词叙事（「进展不错」）当进度；无证据路径标「缺证据」。
6. 失败→回本步：事实源互相矛盾未标主源。

**做到**：三计数器有数字；每条阻塞有 Owner 或已标红代理；来源路径可点开。

### 2. 写摘要结构

**做**
1. 开头固定三行：`红灯 N | 需决策 N | 关键路径健康：…`。
2. 正文按交付包：状态、偏差、下次动作、升级时限；模板周期稳定便于对比。
3. 需决策项单独成块：问题一句 + 选项指针（不替用户拍板）。
4. 数据来源路径写在文末或表头，可被下一手打开复核。
5. 会议只决下次动作，不在会上重写事实行。
6. 失败→回步骤 1：交付包缺状态或无升级时限。

**做到**：结构含三行计数与按包四字段；模板可跨周对比。

### 3. 分发与同步

**做**
1. 分发给制作人/执行圈约定列表；摘要路径登记或挂会话卡。
2. 与 `sync-state` 对齐后再发，避免多频道漂移拷贝。
3. 阻塞项必须有下次动作与升级时限，否则不得标「已跟进」。
4. 不写战斗 Buff/控制态/叠层互斥（另技能）；不写情绪催工文。
5. 失败→回步骤 2：分发稿与事实源字段不一致。

**做到**：摘要已分发且路径可引用；阻塞有动作与时限；与会话卡一致。

## 完成检查

- 摘要含三行计数与可复核交付包状态
- 阻塞项有下次动作与升级时限
- 无战斗状态规则正文；无形容词冒充进度

## 失败回哪一步

- 多源矛盾、缺 Owner → 回步骤 1（先 `sync-state`）
- 缺三行计数或包四字段 → 回步骤 2
- 分发与事实源漂移 → 回步骤 3

下一步常接：`sync-state`；`risk-register-update`；`associate-producer` / `project-manager`。

## 不在此文件

- 战斗 Buff/控制态规则配方
- 产品表细则
- 情绪催工文

## 工具锚

- `~/.cursor/skills` / `agents` / `mcp.json`
- `~/.cursor/skills/`、`~/.cursor/agents/`：正文与职种落点
- `.harness/sessions/<会话>/loadplan.json`、`activated.json`：本会话能力名单
