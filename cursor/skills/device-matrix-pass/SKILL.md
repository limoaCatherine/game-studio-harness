# 设备矩阵怎么验

真机分层抽样（低/中/高 RAM 与 GPU 族）：功能冒烟 + 热/帧稳 + 降级开关可观察回预算。分辨率只作矩阵一列，不是兼容结论主体。长会话帧时/p50/p99/预算对照下钻交 `perf-budget-check`。

## 何时用

- 发行前要按档位机型抽样验收
- 低端机爆热/掉帧、长会话后性能腰斩
- 降级开关是否真生效（手动与自动热触发）
- 商店最低规格声明与实机能力要对齐

## 怎么做

### 1. 冻结必测矩阵（风险抽样）

1. 向用户索取最低规格声明与目标区安装分布；无数据用低/中/高 RAM·GPU 默认骨架，矩阵头标注「待用安装数据替换」。
2. 建矩阵表列：`device_id`、`tier`、`OS`、`RAM`、`GPU` 族、`OEM`、**分辨率（仅一列输入）**、`输入`、`画质默认`、`构建槽`、`must_test`。
3. 低端至少 1 台靠近最低 RAM；GPU 族覆盖两类以上；不得只有旗舰。模拟器/云真机单列，不顶真机结论。
4. 冻结场景清单：冷启、登录、主路径、存档、最差战斗/拥堵、旋转+前后台。
5. 检查：低端行存在、每机绑定构建槽；缺最低规格则停在本步不发机。

**做到**：必测矩阵含低中高档与场景清单；低端机在列；分辨率未写成结论主体。

### 2. 每机功能冒烟可勾选

1. 装包校验哈希/版本名与构建号一致后按场景清单执行。
2. 每机填结果表：`case_id`、`result`、`symptom`、`shot_path`、`log_path`。
3. 覆盖存档杀进程读写、安全区/触控死区、旋转与 Home 前后台（含战斗中）；主机/PC 补手柄断开提示与窗/全屏切换。
4. 失败标签含 `device+OS`；同现象多机链同一缺陷 id。
5. 检查每机功能项全有结果；FAIL 必有证据路径。

**做到**：每机功能冒烟有勾选结果与证据；机型标签齐全。

### 3. 热与帧稳采样

1. 长会话按冻结时长跑；记帧时分布与热节流是否触发（可观察信号即可，不做预算系统下钻）。
2. 对照档位画质默认；记录节流后可玩性变化与回升。
3. 编辑器/模拟器样仅对照，真机结论单列。
4. 异常开缺陷挂机型标签；附帧时或温度可观察信号。
5. 检查冷热/长会话项有记录；不合格补跑本步。超标需分桶/profiler 下钻 → 交 `perf-budget-check`。

**做到**：热/帧稳有可观察记录；不冒充预算专项结论。

### 4. 验证降级开关可观察回预算

1. 手动切低画质档与自动热触发各验一次；观察 HUD/设置项/日志开关值。
2. 确认降级后帧时或负载回到约定观察区间，或记录未回并开单。
3. **分辨率只作为矩阵一列输入**，不把「多分辨率适配全文」写成兼容/矩阵结论主体。
4. 汇总矩阵版本号与本轮结果摘要交制作/兼容职种。
5. 检查开关可观察且有前后对比；空口「感觉稳了」退回补证据。

**做到**：降级开关有可观察前后记录；模拟器不顶真机结论。

## 做到

- 必测矩阵含低中高档与场景清单；低端机在列
- 每机功能冒烟有勾选结果与证据；机型标签齐全
- 热/帧稳与降级开关有可观察前后记录；模拟器不顶真机结论

## 工具锚

- CI 流水线配置（`.yaml` / workflow）与冒烟命令日志
- 失败用例名与复现步骤写入 `.harness/artifacts/`
- `verify-report.json` 引用本批日志路径

## 失败回哪一步

- 只有旗舰、缺最低规格、场景未冻 → 回步骤 1
- 失败无机型标签、项缺结果 → 回步骤 2
- 无热/帧记录、模拟器顶真机 → 回步骤 3
- 降级未验证、空口感觉稳 → 回步骤 4

## 边界

- 不做：纯分辨率适配 UI 规范全文；性能预算对照与 profiler 下钻全文（→`perf-budget-check`）；商店认证条款逐条（→`platform-cert-smoke`）；功能深度用例库
- 下一步常接：超标 `perf-budget-check`；机型相关认证短项 `platform-cert-smoke`；N/N-1 存档协议 `compat-smoke`
