# 规则可行性怎么判

## 何时用

- GDD 规则疑似超引擎或联机能力
- 工期内无法完成的规则需降级
- 程序与策划对可行性有争议
- 需要可回写 GDD 边界的判定包

## 怎么做

### 1. 拆规则为能力点

**做**
1. 从 GDD 抽出规则，拆成能力点行：`rule_id | capability | 输入 | 输出 | 实时性(帧内/局内/可异步) | 精度 | 持久化 | 联机需求`。
2. 标依赖未设计系统；知识缺口写成「问谁 / 查什么文档/Profiler 计数」。
3. 区分「体验承诺」与「实现手段」；手段可换，承诺降级须评支柱损伤。
4. 列出本轮进判定的 rule_id 与延后项；延后写为何不挡本里程碑。
5. 输出能力点表路径；缺引擎/网络数字向用户或程序索取，不编造 tick。
6. 能力点无实时性等级：回本步补齐再对照约束。

**做到**：规则拆成可验证能力点；实时性与知识缺口可执行。

### 2. 对照引擎/网络 tick/人力做判定

**做**
1. 引擎约束锚：查项目引擎文档或先例（如同屏单位上限、物理查询预算、动画 Mask 限制）；能开 Profiler/Stat 的记下相关计数器名（如 `Gameplay/ActiveActors`、`Stat Unit`）。
2. 网络 tick 锚：写清服务器帧/ tick Hz、客户端预测窗口、可回滚深度（向网络/程序确认）；能力点若要求「帧内权威同步全客户端」而 tick 不够 → 标红。
3. 逐条判定：`可行 / 条件可行 / 不可行`；条件写清（要 ADR / 砍精度 / 加人力 / 改异步 / 降联机）。
4. 联机权威灯：`红=需 ADR` / `黄=条件可行` / `绿=已有先例`；红灯必须开 ADR 旗标字段 `adr_needed=true`。
5. 每条判定挂依据槽：`引擎文档锚 | Profiler 计数器 | 工程师确认记录路径 | 先例 skill/系统名`；口说无槽=无效判定。
6. 人力/档期：估人日粗档与本里程碑剩余；超档则条件可行或不可行，不口头「赶一赶」。
7. 依据槽空：停在本步补确认。

**做到**：每条判定有约束依据；网络 tick 与 ADR 旗标显式；红灯必标 adr_needed。

### 3. 降级选项与回写

**做**
1. 对条件/不可行项给 2～3 降级：减精度 / 表现骗 / 改异步 / 砍联机特性 / 砍规则；各写支柱损伤（高/中/低）与是否可回滚承诺。
2. 用户选定后回写 GDD 边界段落或 ADR 指针；引用本判定表版本号；未回写不得称「已降级落地」。
3. 降级影响字段/事件：列变更清单；表变更走 `excel-com-write` → `tunable-table-diff`。
4. 不可行且用户坚持原规则：升级为范围/里程碑决策，附影响面，不在本 Skill 硬做。
5. 输出：`选用降级 | 支柱损伤 | 回写位置 | adr_id或空 | 残留风险`。
6. 回写位置找不到：回本步定位 GDD 节名；ADR 红灯未立项则开 ADR 草稿链再往下。

**做到**：不可行项有可选降级；回写位置可点；ADR 红灯有草稿或 id。

### 4. 收口判定包

**做**
1. 判定包文件含：能力点表、判定表、降级选用、回写位置、ADR 旗标汇总、残留风险；路径写入任务。
2. 与 `feature-gdd-slice` 未决项对勾：已回写的从阻塞挪到已裁。
3. 表/事件变更清单交 excel 路径或程序接口任务。
4. 无路径口头传达「能做/不能做」→ 无效，必须补判定包。
5. 抽检：任选一红灯能力点，能指到 tick/Profiler/文档依据与 ADR 旗标；指不到回步骤 2。
6. 阻塞 vs 可延后分列；可延后写里程碑理由。

**做到**：判定包可引用；回写可追踪；红灯均有 ADR 旗标处置。

下一步常接：回写 `feature-gdd-slice`；`promote-adr`；表变更 `excel-com-write`。

## 细则

### A. 拆能力点
1. 从 GDD 规则节逐条抽出能力点行：`rule_id|capability|latency|online|deps|gap|verdict`。
2. `latency` 只能填：帧内 / 局内同步 / 可异步；含糊词改写。
3. 联机列：权威模型（主机/服务器/P2P）与反作弊影响一句话。
4. 知识缺口写「问谁/查哪类引擎文档锚」，禁止空「待确认」。
5. 失败→回 GDD：规则无法拆成可测能力点则先改规则表述。

### B. 判定与降级
1. 判定仅允许：可行 / 条件可行 / 不可行；每条挂依据槽（文档锚或工程师确认记录路径）。
2. 权威灯：红=需 ADR，黄=条件可行，绿=已有先例；红灯不得标可开做。
3. 条件/不可行必须给 2～3 降级：减精度 / 表现骗 / 改异步 / 砍联机 / 砍规则，并标支柱损伤高中低。
4. 选用降级后回写 GDD 边界，引用本判定表 `feasibility_version`。
5. 经济/战斗交叉字段拉数值职种会签；坚持原规则且不可行→升级里程碑决策。

### C. 闭合检查
1. 抽 3 条规则走读：能力点→判定→降级/通过→GDD 边界是否已更新。
2. 信号：缺依据槽、红灯仍进实现队列、降级无支柱损伤标注。
3. 工具面：表格、版本库 diff、引擎文档检索、ADR 草稿路径。
4. 与 `server-api-contract` 冲突的权威假设单列。
5. 不合格回步骤 B 或回 GDD 改规则。
