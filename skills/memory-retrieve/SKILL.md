# 开工前怎么检索记忆

## 何时用

- 制作前要避免与已批准事实冲突
- 用户问「上次怎么定的」「有没有决策/产物可复用」

## 怎么做

### 1. 收成检索键

**做**
1. 从用户问题抽出 3～7 个键：系统名、表名、接口、属性主键、工作项 id、职种名。
2. 写清本题要回答什么（一句话）；超出范围标「本次不检索」。
3. 不合格：键全是空话（「弄好」「那个」）→ 先问清再检索。

**做到**：检索键列表 + 本题一句话可指。

### 2. 按固定顺序读

**做**
1. 先读现行卡 `.harness/sessions/<会话>/current.md`，再用加载计划 `retrieve_keys`（无则用步骤 1 的键）。只打开命中条目，不扫全库。
2. 已批准事实库：`.harness/memory/canon/`。
3. 架构/技术决策：`.harness/memory/adr/`。
4. 产物索引：`.harness/artifacts/index.jsonl`（按键过滤 path/summary）。
5. 会话/交接：当前会话目录、`.harness/artifacts/**/handoff.md`。
6. 每个来源至少打开命中文件正文，不只扫文件名。
7. 不合格：目录不存在 → 记「缺库」，不假装检索过。

**做到**：四类来源都查过或显式记缺；命中处有原文位置。

### 3. 列出命中并处理冲突

**做**
1. 每条命中写：陈述摘要、路径、状态（有效/废弃/未知）、与本题关系（直接约束/背景/无关）。
2. 冲突条目并列，不擅自挑边；请用户选。
3. 只陈述读到的内容，不发明「应该还有」的决策。
4. 把命中列表交给定档/制作引用；需要晋升新事实时转 `promote-canon` / `promote-adr`。
5. 不合格：把讨论档口头想法写成「已批准」→ 删改并回步骤 2。

**做到**：命中表可交给下一手；冲突已并列。

## 完成检查

- [ ] 检索键与本题清楚
- [ ] 四类来源已查或记缺
- [ ] 命中带路径与状态；冲突已并列

## 工具锚

- `.harness/memory/canon` `adr` `status`
- `.harness/artifacts/index.jsonl`
- `.harness/sessions`、`handoff.md`
- 全文/文件名检索（编辑器搜索或 rg）

## 失败回哪一步

- 键不清 → 步骤 1
- 目录缺/未打开正文 → 步骤 2
- 误标已批准 → 步骤 3
