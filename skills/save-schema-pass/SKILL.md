# 存档 Schema 怎么验

## 何时用

- 存档格式变更或迁移丢数据
- 坏档导致崩溃
- 要加防篡改基础校验与钳制
- 热更后旧档进新客户端

## 怎么做

### 1. 冻 schema

1. 写现行版本号、字段类型、默认值；可信字段 vs 钳制字段分两列（货币/体力默认钳制）。
2. 校验顺序：先版本/结构校验再读业务字段；路径固定根目录+文件名白名单，不拼接玩家输入串。
3. 改义同名字段必须升版本，不在原地改义；版本字段位置（键名或偏移）写清。
4. 与 API 契约/热更轨对齐：哪些字段可缺省、哪些加载后必须钳制写进表注。
5. 输出 schema 表（表格文件写入走 `excel-com-write`）。

**做到**：schema 与版本字段冻结；钳制规则显式；字段类型/默认可指。

**不合格**：版本字段位置不清或先读业务再校验 → 回本步。

### 2. 写并测迁移

1. 对每个仍支持的旧版本写迁移：字段映射、默认填充、失败回滚/双读期结束条件。
2. 原子写：先临时新档成功再替换，保留备份；失败删半新档，保留好档。
3. 抽检至少：进度旗标、货币、背包数量；迁移日志记 from→to、耗时、成败。
4. 双读期写清结束条件（版本号或日期）；把「旧档升级」用例路径写进 fixtures，供 `compat-smoke` 消费。

**做到**：迁移可跑且失败保留好档；抽检关键字段正确。

**不合格**：覆盖好档或抽检丢关键进度 → 回本步修迁移。

### 3. 加载校验

1. 实现校验和/签名（若有）、必填、数值范围；失败原因码可读且日志含版本。
2. 失败处置：拒绝加载、隔离坏档副本、保留好档、提示重建。
3. 安全反序列化；检索确认无信任档内货币直加钱包；路径 traversal 用例应拒。
4. 原因码分玩家可见 vs 内部；拒收日志可检索。

**做到**：非法档被拒且好档仍在；无半写脏档；拒收日志含原因码。

**不合格**：非法档未拒或半写脏档 → 回本步补校验。

### 4. 坏档演练

1. 检入三类 corrupt fixtures：缺字段 / 越界货币 / 截断；期望提示+隔离+可建新档，无崩无脏写。
2. 演练进 CI 或 nightly；结果记构建号+样例名+成败。
3. 链 `compat-smoke` 的 N-1 旧档进 N 格；演练失败不得宣称存档链路可用。

**做到**：三类坏档演练通过；样例可回归；版本升级链有记录。

**不合格**：样例缺或未挂自动化 → 回本步补样例与钩。

## 做到

- schema 与版本字段冻结；钳制规则显式
- 迁移可跑且失败保留好档；抽检关键字段正确
- 三类坏档演练通过；非法档拒收日志可检索

## 失败回哪一步

- 版本字段位置不清、钳制列空、先读业务再校验 → 回步骤 1
- 迁移覆盖好档、抽检丢货币/进度 → 回步骤 2
- 非法档未拒、货币直加钱包、traversal 未拒 → 回步骤 3
- 坏档样例缺、CI 未挂、N-1 未测 → 回步骤 4

下一步常接：`compat-smoke`；安全面 `anti-cheat-hook-check`。
