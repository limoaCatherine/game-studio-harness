# 功能 GDD 怎么按节共写

## 何时用

- 新功能需要可实现的 GDD 切片
- 规则仍停留在口头传说
- 已有 GDD 要 retrofit 空洞节
- 跨职种接口或公式/验收句缺失

## 怎么做

### 1. 读上下文与定范围（索引 + rg）

**做**
1. 必读：支柱、`systems-index-map` 本条、上游 GDD、实体/公式登记；用 `rg -n "系统名|公式名|常量" design/ gdd/` 摘硬约束到 `gdd/<sys>_constraints.txt`（含文件:行号）。
2. 已有 GDD：标哪些节已写/仅占位；列将填节/不动节；用 `git diff` 或文档锁保护已写节。
3. 模式：新建 / 续写空洞 / 仅审计；禁改区与可测成功标准写入 `gdd/<sys>_scope.md`。
4. 依赖未设计标 `provisional` 进未决；冲突表在开写前呈报用户裁断。
5. 打开系统索引确认 `sys_id` 状态；无行则先补索引再写 GDD。
6. 失败→回本步：索引无本系统行、冲突未裁、或成功标准无证据类型——补齐再落骨架。

**做到**：scope 含模式/将填/不动/禁改/成功标准；constraints 有行号摘录；provisional 显式；sys_id 可指。

### 2. 落骨架（八节序写死）

**做**
1. 骨架节文件 `gdd/<sys>_slice.md`：目标/玩家幻想、用户流程、核心规则与状态、公式、数据字段、接口与依赖、边界/非目标、验收与未决。
2. 每节仅标题+「待共写」一句；逐节选项→批准，不一次灌全文。
3. 节序写死：规则→公式→字段→接口（微调须用户确认写入 scope）。
4. 进度板（看板列或文首表）：每节 `todo|options|draft|approved`；批准一节再开下一节。
5. 骨架路径与命名约定写入 scope，供增量编辑锚定。
6. 缺项目数字/档位向用户索取；标假设条目不得当事实引用。
7. 失败→回步骤 1：成功标准不可测——改 scope 证据类型再搭骨架。

**做到**：八节标题齐；进度板可勾；节序在 scope 冻结；无全文逼签；假设已标。

### 3. 逐节共写（选项→批准）

**做**
1. 节循环：Context（要回答+上游约束）→ 2～4 选项+利弊 → 用户决策 → 草稿 → 批准 → 下节。
2. 规则节：Given/When/Then 可测陈述；例外单列；每条规则可派生测试意图一句。
3. 公式节：命名表达式、变量表（符号/类型/范围/含义）、输出钳制；`rg` 变量名对齐 `attribute-framework`。
4. 数据字段：列候选 `sheet.col`；实写产品表走 `excel-com-write`，GDD 只留设计 SoT。
5. 接口节：事件名/表字段/UI 需求槽；与下游冲突并列选项请用户裁。
6. 用户流程节：主路径步骤 id 可被 `ux-flow-spec` 引用；异常一句指针即可，细流另开。
7. 失败→回本步上一节：未批准就开写 / 变量不在属性框架——停写，回批准或补框架。

**做到**：关键节有选项记录+批准标记；规则可测；公式含变量表与钳制；字段有 sheet.col；流程步可引用。

### 4. 冲突扫描与收口（验收证据）

**做**
1. `rg` 实体名/公式名/常量 vs 登记与上游；不一致立即并列冲突卡（两选项+推荐）请用户裁。
2. 验收句每条绑证据类型：录像时间码 / 日志键 / 表 diff 路径 / Test Runner case id。
3. 可行性存疑交 `rule-feasibility-check`；不假装已实现。
4. 输出冲突表、验收表、未决表；切片状态 `deliverable|blocked`；回写系统索引状态字段。
5. provisional 依赖汇总并标是否阻塞实现开工；阻塞则队首不得进开发看板。
6. 失败→回步骤 3：冲突未并列或验收无证据类型——回对应节补完再交付。

**做到**：未裁决冲突=0 或全并列；验收句可测；索引状态已回写；阻塞可见。

下一步常接：`systems-index-map`；`rule-feasibility-check`；测试派生另开 QA Skill。

## 细则

### A. 范围卡与证据类型
1. `gdd/<sys>_scope.md` 必须含：模式、将填节、不动节、禁改区、成功标准、证据类型（录像/日志键/表 diff）。
2. 成功标准每条挂「观察什么」；只有形容词（更好/更爽）则退回改写。
3. 上游未锁依赖标 `provisional`，并在未决表写「卡谁/是否挡本里程碑」。
4. 用 `rg` 把支柱否决例子贴进 constraints；撞否决的功能不得进将填节。
5. 失败→回读上下文：索引无 `sys_id` 或冲突未裁断。

### B. 八节共写循环（可执行）
1. 进度板状态机：`todo→options→draft→approved`；未 approved 不开下一节。
2. 规则节写成「给定/当/则」；状态机必须有表或图作唯一源，散文只能注释。
3. 公式节：表达式命名 + 变量表（符号/类型/范围/单位）+ 输出钳制；缺单位标阻塞。
4. 接口节列：输入事件、输出事件、表字段、存档键、UI 槽；命名稳定后才可给工程。
5. 验收句与 QA 用例键对齐；范围外「不做」清单不少于 3 条可感知项。

### C. 冲突与变更
1. 与 Canon/登记表冲突时并列两边+影响面，禁止静默选边。
2. 节批准后改动走变更条：改了哪节、谁受影响、是否要回可行性检查。
3. 切片状态：草稿→可开做→冻结；冻结后改接口必须升 `rule-feasibility-check`。
4. 交付物路径写入任务备注，供 `artifacts-append`。
5. 不合格信号：接口事件名与客户端竖切不一致、或验收无证据类型。
