# 产物怎么登记进索引

## 何时用

- 本段产出多份文件，或换手需要完整路径列表
- 短活结案只登记验证报告时走 `verify-gate`，不点本技能

## 怎么做

### 1. 列出待登记项

**做**
1. 每项写：路径、类型（文件/目录/报告）、一句话摘要、关联 `bead_id` 或会话 id、产出技能/职种 id。
2. 路径优先工作区相对或绝对；每行必须是可打开路径，不用指代代替 path。
3. 同一逻辑产物多版本时，每版本一行，摘要里写版本差异。
4. 不合格：缺工作项或摘要空 → 补全。

**做到**：清单每行字段齐全。

### 2. 核验路径真实

**做**
1. 逐个确认路径存在；文件非空；目录内至少有一个有效文件。
2. 打不开的标「缺失」并从本批剔除或先生成再登记。
3. 敏感密钥文件不登记内容、不登记路径到共享索引（改登记「密钥在密钥管理处」说明行）。
4. 不合格：路径未核验通过 → 停写索引。

**做到**：本批每一路径都核验通过。

### 3. 追加写入索引

**做**
1. 目标文件：工作区 `.harness/artifacts/index.jsonl`（无则创建，UTF-8）。
2. 每行一个 JSON 对象，字段至少：`ts`（ISO时间）、`bead_id`、`skill`、`path`、`summary`。
3. **只追加**：同一 path 再产出时追加新行，不删旧行。
4. 先出示将追加的 JSON 行；获准后再写入。
5. 写后回读最后 N 行，确认本批行在。
6. 不合格：回读不见本批行 → 重写追加并再回读。

**做到**：index.jsonl 尾部可见本批行；用户已确认过预览。

## 完成检查

- [ ] 路径核验通过
- [ ] 预览获准后已追加
- [ ] 回读见到本批行

## 工具锚

- `.harness/artifacts/index.jsonl`
- 文件系统存在性检查
- 验证报告 `evidence_paths` 应能引用本索引中的路径

## 失败回哪一步

- 清单字段不全 → 步骤 1
- 路径缺失 → 步骤 2
- 写入/回读失败 → 步骤 3
