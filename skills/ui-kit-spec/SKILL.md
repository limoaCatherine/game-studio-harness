# UI 组件库怎么定规格

## 何时用

- 要建或扩展可复用 UI Kit；各屏私造控件成灾
- 状态/尺寸不统一；缺禁用/加载/错误态或 a11y 角色
- 程序难实现因设计只有理想态一张图

## 怎么做

### 1. 盘点分层（截图墙 + 命名）

1. 导出/截取现网或现包 UI 屏到 `ui/audit/`；在 Figma 建截图墙，把控件拖到原子/分子/模板三层框。
2. 打开 Figma Components 面板与引擎 UI 库（UGUI Prefab 目录 / UI Toolkit UXML / Unreal UMG Widget）；导出已有组件名列表。
3. 同义异名合并：表 `old_name → kit_id`；kit_id 用项目 token（如 `btn.primary`/`list.row`）。
4. 在本仓 UI 预制 / 脚本根检索 Button/Toggle/Modal/Dialog，列出私造路径。
5. 向用户确认本里程碑出库范围（哪些原子必须先齐）；README/索引写「kit 外新控件走申请+到期日」。

**做到**：分层盘点表含 kit_id/层/是否出库；私造扫描路径列表可点；出库范围冻结。

### 2. 写组件合同（token + Variant）

1. 每组件合同字段：用途、变体、尺寸档、状态集（默认/悬停/按下/焦点/禁用/加载/错误）、内容槽、文案最大长度、事件名槽。
2. 在 Figma 用 Variants 搭状态矩阵；绑定 Design Tokens（Figma Variables 或 `tokens.json` 色/间距/圆角/字号）。
3. 出库前补齐禁用/加载/错误态；危险操作组件必须含确认或可撤销说明槽。
4. a11y：焦点顺序、角色名（button/dialog）、对比度——用对比度插件或引擎 Accessibility；信息不止靠色相。
5. 尺寸档对齐栅格（项目约定，如 8pt）；程序备注写回调名，避免「点一下就行」。
6. 每个出库组件导出默认|禁用|错误三态并排 PNG 供程序对照。

**做到**：出库组件 Variant 状态集完整；token 有引用路径；三态并排样例已导出；对比度检查通过或挂例外 id。

### 3. 引擎对齐与索引出库

1. 引擎侧建/核同名 Prefab/UXML/UMG；在 Play 模式切 Disabled/Loading/Error，Inspector 确认可见反馈。
2. 输出 kit 索引：`kit_id|version|figma_url|engine_path|states`；供 `ui-screen-pass` 文首引用。
3. 列旧屏私造→kit 映射优先序；抽 2 个旧屏做迁移可行性记录——不可行则补组件或批例外（到期日写入例外表）。
4. 模板级列必填槽与校验时机（提交前/失焦）；通知设计+程序：新屏引用索引 id。
5. 引擎态与 Figma Variant 不一致（缺灰态等）→ 回步骤 2 改合同或改实现后再进索引。

**做到**：索引可被单屏引用；引擎抽样三态可见；≥1 旧屏映射结论（可行/例外）写明。

### 4. 维护、私造扫描、a11y 回归

1. 准入：需求→可复用判断→合同草案→入索引；一次性私造走例外表（路径、理由、到期日、批准人）。
2. 改合同必须升版本；`rg kit_id` 列影响屏并通知 Owner；单屏职责卡引用栏写 kit 版本。
3. 定期私造扫描：截图 diff 或 `rg` 新增 UI 文件；命中回流映射表。
4. a11y 回归：键盘/手柄走主路径焦点环；失败→回步骤 2 补角色名或焦点顺序。
5. 文案最大长度与 `copy-pass`/L10n 预留对齐；超长在合同标红。
6. 例外过期未清→关闭例外或转正组件后再标扫描通过。

**做到**：例外表有到期；合同变更可追溯到影响屏；焦点路径可走通；私造扫描有最近一次日期。

## 做到

- 原子/分子/模板分层与 kit_id 清晰；出库组件状态集完整且 Figma+引擎一致
- Design Tokens 引用明确；a11y 角色与对比度写清
- kit 索引可引用；旧屏映射或例外有到期；私造扫描有记录

## 失败回哪一步

- kit_id 冲突、截图墙空 → 回步骤 1
- Tokens 未建、Variant 缺禁用/加载/错误 → 回步骤 2
- 引擎态与 Figma 不一致 → 回步骤 2 再进步骤 3
- 例外过期、焦点环断、私造回潮 → 回步骤 4（必要时回 3 补索引）

下一步常接：`ui-screen-pass`。
