# 里程碑怎么排

## 何时用

- 版本/里程碑目标要落地，范围与容量不匹配
- 跨职种交付顺序争议；需要可演示 DoD 而非「合并即完」
- 开裁剪或风险台账前需要目标锚

## 怎么做

### 1. 定目标与成功证据

1. 写玩家可感知目标句 + 非目标清单；目标句可演示/可度量，不用「做得更好」「更稳定」空话。
2. 成功证据写成可演示步骤：谁、在哪个构建号/分支、点哪些入口、看到什么；指标口径向用户索取。
3. 打开 `systems-index-map` / 依赖图：标必须系统 vs 可裁；必须项逐条映射到证据勾选框。
4. 对齐支柱卡 PillarID：本里程碑证明哪几句；证明不了的「想做」降可裁或移出。
5. 在里程碑板（Jira/Linear/Notion）建史诗卡字段：目标、证据、Must/Should/Stretch、冻结日（内容/配置/代码）、不做清单。
6. 无目标日期则先向用户要日期再排包；日期写入日历工具。

**做到**：史诗卡字段齐全；Must 项均映射证据勾选；冻结日与不做清单可见。

### 2. 切范围对容量（人周）

1. 建工作包表（sheet）：`pkg_id|type|estimate_pw|deps|owner|on_critical|notes`；类型含系统/内容/技术债/活服；表写入走 `excel-com-write`。
2. 容量计算：可用人周 × (1-会议折损) × 并行面系数——折损与系数向用户索取，写入容量格。
3. 缓冲%按项目档填写；判定式：`Σ estimate_pw ≤ 容量×(1-缓冲%)`；超出则给 2～3 套范围包+利弊，或转 `scope-cut-decision`。
4. DoD 列表只收可演示项；「已合并」「已画完」alone 不算完。
5. 内容包对照 `liveops-calendar` 与关卡列表；超产能活动/关卡当场降标或挪期。
6. 技术债：只收「挡成功证据」的债；漂亮重构进美化池，不占关键路径；`on_critical=true` 必须有 Owner。

**做到**：容量格可复核；不等式成立或已选裁剪包；DoD 可演示；关键路径无空 Owner。

### 3. 关键路径、信号、日历交接

1. 按 deps 在看板泳道或甘特排串行链与并行面；标外部依赖到达日（平台/合规/外包/认证）。
2. 关键节点写早期信号：CI 红灯、试玩日构建、表锁日 diff、素材到仓日——信号可在工具里订阅（CI/日历提醒）。
3. 高风险写缓解并挂 `risk-register-update`（risk_id 链接）。
4. 变更规则写进史诗：加项必须同等裁项或延后；审批人槽；静默加项记违规。
5. 日历写入交接日：策划锁表日、程序可玩日、试玩日、活服配置冻结日、中段预演日、里程碑日。
6. 输出一页计划 md/页：目标、包表摘要、关键路径、缓冲、风险指针、DoD、交接日。

**做到**：关键路径在板可跟踪；交接日在日历可点开；高风险有 risk_id；变更规则可见。

### 4. 跟踪、中段预演、收口

1. 站会看关键路径漂移与缓冲消耗（看板燃尽/剩余人周）；漂移超缓冲→触发重排或 `scope-cut-decision`。
2. 中段按成功证据步骤跑「假演示」并录像/截图；失败则早裁或降标（回步骤 2）。
3. 结束对照 DoD 勾选；未达项写去向（下里程碑/砍/风险接受）并通知下游 Owner。
4. 归档：计划版本 vs 实际偏差表（估点、日期）；偏差大的包类型标「估点不可信」供下轮。
5. 含活服上线：核对日历开启日与构建号、开关名同一事实（后台点验）。

**做到**：中段预演有证据文件；结束去向清楚；偏差表归档；活服开关名与日历开启日同一事实。

## 做到

- 目标句可验收且有演示证据步骤
- 容量公式下范围可装入（含缓冲）或已选裁剪包
- 关键路径与外部依赖明确；Owner 齐全；交接日与预演日在日历
- DoD 勾选或去向明确；变更规则写明

## 失败回哪一步

- 证据无法在现包演示且无替代 → 回步骤 1 改目标或降 Must
- Owner 空却 on_critical、超容量硬塞 → 回步骤 2（或转裁剪）
- 关键路径工期 > 剩余日历工作日 → 回步骤 2 砍包或改里程碑日（步骤 3 重排）
- 预演失败且无裁剪提案 → 回步骤 3 停承诺，回板改范围后再宣佈（步骤 4）

下一步常接：`scope-cut-decision`；`risk-register-update`。
