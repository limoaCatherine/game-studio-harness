# 回归包怎么组与怎么跑

按影响组包执行；已修必回归；索引可检索。

## 何时用

- 版本回跑或热更前
- 修缺陷后要防复发
- 覆盖漂移要审计

## 怎么做

### 1. 定包结构与可检索索引

1. 对照 `tests/regression-suite`（或等价）与脚手架目录/模块标签约定。
2. 索引列写死：`case_id`、`module_tag`、`priority`、`auto`、`bug_id`、`last_green_build`、`status`。
3. 摘要头：包大小、自动占比、STALE/QUARANTINED 计数、锚定构建号。
4. 手工与自动分行；模块标签与变更模块名一致便于过滤。
5. 检查第三人能按 tag 筛出本版包；摘要与行数一致。

**做到**：可检索索引与摘要头存在；七列齐全。

### 2. 已修缺陷入库与影响组包

1. 本里程碑已关缺陷必须有回归条；文件名或注释含 `bug_id`；无则 `MISSING_REGRESSION` 回灌 `test-case-from-gdd`。
2. 按变更模块与触文件 callers 闭包（hotfix）圈影响组，**生成执行队列**（入库与组包连贯完成）。
3. 崩溃/丢档/付费类强制 P0；重复条合并留更严断言。
4. 检查已关 P0 无 MISSING；影响组与队列 `case_id` 可对上。
5. 不合格：已修无回归条 → 回本步补。

**做到**：已修缺陷有回归条；影响组已生成执行队列。

### 3. 按影响组执行队列

1. 先跑影响组内 P0 再 P1；P0 红默认停扩 P1（除非用户明示带伤）。
2. 每条记 `result`、`evidence`、`duration`、构建号；片状 quarantine 不装绿。
3. **环境失败与产品失败分栏**；环境红不灌产品缺陷库。
4. 执行率=已跑/计划；未跑项写原因。
5. 检查队列结果可复核；不合格回本步补证据。

**做到**：本轮按影响组执行完；P0/P1 结果与证据可复核；环境/产品分栏。

### 4. 缺口回灌与包维护

1. STALE 重跑或写废弃原因；漂移项三选一：补测/接受风险/另迭代。
2. 缺口与 MISSING 回灌用例或映射；PR/变更说明三行：新增/废弃/缺口变化。
3. 更新 `last_green_build` 与摘要头；quarantine 逾期暴露。
4. hotfix 最小闭包跑完后归档本轮 queue 与构建号。
5. 检查摘要可引用；开放缺口有 Owner。

**做到**：缺口/MISSING/STALE 有处置；包摘要已更新锚定构建号。

## 做到

- 可检索索引与摘要头存在；已修缺陷有回归条
- 本轮按影响组生成并执行队列；P0/P1 结果与证据可复核
- 缺口/MISSING/STALE 有处置；包摘要已更新锚定构建号

## 失败回哪一步

- 索引缺列、摘要与行数不一致 → 回步骤 1
- 已修无回归条、影响组未生成队列 → 回步骤 2
- P0 红仍扩 P1、片状装绿、环境红灌产品库 → 回步骤 3
- 漂移无去向、摘要未更新 → 回步骤 4

## 边界

- 不做：从零写全量用例库；CI 脚手架与 quarantine 政策正文（→`auto-test-scaffold`）；性能预算采样规程；验收签字口径终裁（→`qa-lead`）

## 工具锚

- CI 流水线配置（`.yaml` / workflow）与冒烟命令日志
- 失败用例名与复现步骤写入 `.harness/artifacts/`
- `verify-report.json` 引用本批日志路径
