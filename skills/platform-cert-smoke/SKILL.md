# 平台认证冒烟怎么跑

宜短清单。**不做性能预算下钻长文**，性能抽检只保留条款要求的短项；预算全文交 `perf-budget-check`。

## 何时用

- 提审前或审核拒后复测
- 权限/支付/登录流程变更
- 隐私披露与实际上报行为要核对

## 怎么做

### 1. 列目标店短清单

1. 确认商店名与条款版本日期；拒审邮件拆成复测项置顶。
2. 写 `cert/<store>/<date>/checklist`，列 schema 写死：`item_id`、`clause_ref`、`method`、`expect`、`owner`、`result`。
3. 覆盖权限、支付、登录、截图规格、冷启崩溃、隐私披露要点——宜短可执行，禁「检查一下」。
4. 每项测法落到代码检索/沙箱操作/冷启脚本/文案对照之一。
5. 检查清单头含店名+日期；拒审项优先；条款过期回本步。

**做到**：短清单每项有测法与期望；schema 六列齐全。

### 2. 权限与隐私最小化

1. 对照 Manifest/能力声明 vs 实际调用点，填 permissions 表。
2. 未用权限剔除；首次弹窗时机与隐私文案 vs 实际上报对照。
3. 检索硬编码密钥/明文 token；Release 关冗长调试。
4. 商店数据安全表单与 SDK 行为不一致则开单。
5. 检查申请集=实际用到集；截图路径可点。

**做到**：权限申请集与实际调用一致。

### 3. 支付/登录沙箱与冷启

1. 沙箱跑购买成功/失败/取消/恢复四路径；记错误码与收据或日志 id。
2. 登录：新号/老号/登出/账号切换；正式价素材不得混用。
3. 冷启主路径至约定点：零崩溃；失败留堆栈与复现步骤。
4. 合规截图按店规格归档，无调试水印/假价/未授权商标。
5. 检查四路径与冷启有结果行；缺项回本步补。

**做到**：沙箱四路径与冷启有记录。

### 4. 证据包与分流

1. 失败项打包证据：截图、日志、条款原句、构建号。
2. 功能/性能交叉问题分流到对应职种；**豁免升 QA Lead（Owner+时效+回补）**。
3. **不把性能预算下钻长文塞进本清单**；性能抽检只留条款要求的短项。
4. 输出短结果表：通过/失败/豁免申请中；拒审复测对照原 `item_id`。
5. 检查每失败项有证据或豁免单号。

**做到**：失败有证据包或豁免路径；结果表可复核。

## 做到

- 目标店短清单每项有测法与期望；拒审项优先
- 权限申请集与实际调用一致；沙箱四路径与冷启有记录
- 失败有证据包或豁免路径；结果表可复核

## 工具锚

- CI 流水线配置（`.yaml` / workflow）与冒烟命令日志
- 失败用例名与复现步骤写入 `.harness/artifacts/`
- `verify-report.json` 引用本批日志路径

## 失败回哪一步

- 条款过期、schema 缺列、拒审项未优先 → 回步骤 1
- 未用权限仍申请、隐私文案不一致 → 回步骤 2
- 四路径未齐、冷启仍崩、正式价混用 → 回步骤 3
- 失败无证据/豁免、塞入预算长文 → 回步骤 4

## 边界

- 不做：性能预算全量实测与 profiler 下钻（→`perf-budget-check`）；功能深度回归包；机型矩阵全量兼容结论；商店法务长文
