# 交接包怎么写

## 何时用

- 换职种、换会话、跨助手续做
- 当前手做完一段，下一手必须能不靠聊天记录开工

## 怎么做

### 1. 收集本段事实（只写已发生的）

**做**
1. 从用户原话抄目标与成功标准；改过范围的，写最新边界与「不做」。
2. 列出已选方案/已批准决策：一句话 + 来源路径（决策库/会话备注/变更单）。
3. 列出本段产物：绝对或工作区相对路径；每个路径当场确认存在且非空。
4. 列出未决项：问题、缺谁拍板、建议截止；无未决则写「无」。
5. 风险/禁改：点名禁改列、禁推分支、未获准正式写入等。
6. 不合格：目标空或产物路径打不开 → 停，先补齐再写包。

**做到**：目标、决策、产物、未决、风险五块都有可指内容。

### 2. 建议下一手点名

**做**
1. 打开菜单权威 `~/.cursor/skills`、`~/.cursor/agents`、`~/.cursor/mcp.json`。
2. 建议 1～3 个下一手 `craft`/`skill` id，每项写 ≥8 字 why（对上目标哪一句）。
3. 若下一手要调外接：写建议 `mcp` id。
4. 范围已变：写明「先 route-task 改定档」再制作，不假装名单仍有效。
5. 不合格：建议 id 不在菜单 → 换 id 或走 doctor。

**做到**：下一手 id 可在菜单查到，且 why 能对上目标。

### 3. 先写现行卡，换会话再写交接包

**做**
1. 同一会话续做：更新 `.harness/sessions/<会话>/current.md`（目标、进度、写级别、禁改、下一手）。开场读序以现行卡为准，不靠聊天记录。
2. 换职种或换会话：再写入 `.harness/artifacts/<工作项或会话>/handoff.md`；结构按上两步，不用空模板凑段。
3. 包内路径全部可点击/可打开；过期会话口头结论不写进「已批准」。
4. 跑产物登记（`artifacts-append`）：把 handoff 路径追加进索引。现行卡由生成名单维护，不必重复登记。
5. 把现行卡与交接包路径回给用户；接收方声明已读后再换手。
6. 不合格：未登记索引 → 补登记；接收方说看不懂 → 回步骤 1 补事实。

**做到**：handoff 文件在、索引有行、用户拿到路径。

## 完成检查

- [ ] 五块事实齐全且路径可开
- [ ] 下一手 id+why 可点名
- [ ] 交接包已登记进产物索引

## 工具锚

- 菜单 `~/.cursor/skills` / `~/.cursor/agents` / `~/.cursor/mcp.json`
- `.harness/sessions/<会话>/current.md`
- `.harness/artifacts/**/handoff.md`
- 产物索引 `.harness/artifacts/index.jsonl`（经 `artifacts-append`）
- 会话能力名单（提醒是否需重定档）

## 失败回哪一步

- 事实不清/路径无效 → 步骤 1
- 菜单无 id → 步骤 2
- 未登记或接收方拒收 → 步骤 3

## 工具锚点

对照：输入路径、输出路径、日志、表/schema 回读、diff、截图或命令输出。
完成前打开这些对照物；不合格则返工，不空口过关。
