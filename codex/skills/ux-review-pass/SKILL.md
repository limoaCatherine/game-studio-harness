# UX 怎么评审

## 何时用

- UX 规格或屏初稿完成要审，或多屏交互不一致
- 无障碍缺口要列出，模式库违规要收敛
- 上线前要结构化走查，不只看视觉稿
- 活动/商店等高风险流要单独抬检

## 怎么做

### 1. 加载对照尺子

1. 读：目标 UX 流规格、模式库、无障碍要求、相关 GDD UI 节、命名术语。
2. 定评审模式：单屏/整流程/HUD；列本轮必查清单。
3. 记下邻接屏入口出口应对，避免单屏自洽跨屏断裂。
4. 确认严重度口径与里程碑伤兵政策；无口径则高伤项进待决。
5. 准备证据方式：规格锚点、线框标记、原型路径、构建号。
6. 活动流额外加载活动规格与日历时间窗，过期态必查。
7. 不合格：缺流规格仍开评 → 先补 ux-flow-spec。

**做到**：对照尺子与必查清单已加载；证据方式与伤兵政策清楚。

### 2. 完整性与路径质量

1. 查缺节：目的、入口出口、布局层级、状态、交互、事件、无障碍、空/错/载。
2. 查坏路径：死胡同、主操作不可达、错误无恢复、与 GDD 不一致；写证据与严重度。
3. 主路径与放弃路径各走查一遍；记断点与隐式知识依赖。
4. 高代价操作：确认与可撤销/冷却展示；缺则升严重度。
5. 文案截断/术语漂移/错误不可懂→挂 copy-pass。
6. 跨屏返回栈从深链进系统返回出是否合理。
7. 不合格：问题无证据路径 → 回补证据再分级。

**做到**：问题表每条含证据+严重度；主/放弃路径与高代价已查。

### 3. 热区、误触、无障碍与模式库

1. 触控热区与连点风险；危险操作二次确认样式。
2. 迷失/多点/反馈弱记录带时间码或步骤 id。
3. 无障碍：对比度/聚焦序/读屏标签缺口列表。
4. 模式库违规收敛；同功能多套交互标回并。
5. 真机分辨率抽检。
6. 不合格：阻塞项未分级 → 回标严重度。

**做到**：热区/误触/连点、a11y、模式库项审完；阻塞已分级。

### 4. 回改跟踪与复审

1. 问题表：id、证据、严重度（阻塞/抛光）、Owner、目标文件、状态。
2. 阻塞闭后再标可开做；抛光可进债列表。
3. 复审只验原问题时间码/步骤；回归邻接入口。
4. 输出评审报告与债列表入文档仓。
5. 与 ui-logic / ux-flow 变更联动版本号。
6. 不合格：阻塞未关却称通过 → 回问题表状态。

**做到**：阻塞关闭或升级；复审记录可指；报告与债列表入库。

## 做到

- 对照尺子与必查清单已加载
- 问题表每条含证据与严重度
- 阻塞项已关闭或升级待决；复审记录可指
- 报告与债列表已入文档仓

## 失败回哪一步

- 步骤1（加载对照尺子）：缺流规格仍开评 → 先补 ux-flow-spec。
- 步骤2（完整性与路径质量）：问题无证据路径 → 回补证据再分级。
- 步骤3（热区、误触、无障碍与模式库）：阻塞项未分级 → 回标严重度。
- 步骤4（回改跟踪与复审）：阻塞未关却称通过 → 回问题表状态。

下一步常接：`ux-flow-spec`；`ui-logic-pass`；`ux-designer`；`copy-pass`。

## 工具锚

- UI 预制 / 蓝图路径（`Assets/` 或 `Content/`）
- 流程说明可用 `xmind` 或稿件 `.md`；交互状态表 `.xlsx`
- 真机截图落入 `.harness/artifacts/`

## 不在本文件

- 视觉审美终裁
- 改写系统规则
- 代替 ux-flow 补写整图
- 门禁放行口号
