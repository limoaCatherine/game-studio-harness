# UX 流程怎么定

## 何时用

- 新功能要先画玩家路径再开屏
- 流程出现断点或死胡同，多入口行为不一致
- 要给 UI 屏/逻辑的上游规格
- 无障碍/多输入方式未覆盖，或高成本表单缺草稿策略

## 怎么做

### 1. 定玩家任务与到达上下文

1. 玩家任务一句；到达前状态：资源、位置、紧迫假设写入 brief。
2. 成功完成态与主动放弃态；对照 GDD UI 需求收约束。
3. 旅程段：新手/中期/回流；无旅程图则记假设标待验证。
4. 支柱禁交互（强制弹窗连发等）写入约束。
5. 确认平台与输入主方案；高代价操作单列。
6. 不合格：JTBD 或成功态空 → 回补 brief。

**做到**：brief 含 JTBD、成功/放弃态、输入方案、高代价点。

### 2. 画主路径、入口出口与返回栈

1. 步骤表：step、screen_or_state_id、player_action、system_response、next；主路径闭环到成功态。
2. 入口/出口全集：HUD、深链、邮件、活动、商店回跳；深链补前置。
3. 返回栈：系统返回/UI 返回/手势一致；真机返回键测一次。
4. 可选 vs 强制分开；可选失败不得堵死主路径。
5. 每步目标是否可见；不可见补导航。
6. 不合格：主路径断点或返回键困死 → 回改步骤表。

**做到**：主路径步骤可走通；返回键实测可离开；入口出口全集。

### 3. 五态、异常恢复与多输入

1. 五态：默认/加载/空/错/成功（或项目等价集）；每态有 screen_or_state_id。
2. 异常表：断网/超时/缺资源/权限不足/倒计时结束/库存满→指向恢复态。
3. 高代价：确认/撤销/双确认；不可逆写清。
4. 多输入：触控/键鼠/手柄主路径等价；差异点单列。
5. 多分辨率与横竖约束说明。
6. 不合格：异常无落点或五态缺 → 回补节点。

**做到**：五态（默认/加载/空/错/成功）与异常流均有稳定节点 ID；多输入等价。

### 4. 数据、事件与交接

1. 数据依赖与事件槽命名；与 ui-logic-pass / 系统状态机字段对齐。
2. 节点 ID 稳定；缺状态先回系统 GDD，不画空屏。
3. 输出：brief、步骤表、异常表、五态图、高代价清单。
4. 交接 UI/程序/文案；主路径点击次数上限建议。
5. 入库文档仓打版本。
6. 不合格：下游需猜节点 ID → 回补命名。

**做到**：交接包入文档仓；节点 ID/事件槽可对系统与 ui-logic。

## 做到

- brief 含 JTBD、成功/放弃态、输入方案、高代价点
- 主路径步骤可逐步走通；返回键实测可离开
- 五态与异常流均有稳定节点 ID
- 交接包已入文档仓且字段名可对系统/UI 逻辑

## 失败回哪一步

- 步骤1（定玩家任务与到达上下文）：JTBD 或成功态空 → 回补 brief。
- 步骤2（画主路径、入口出口与返回栈）：主路径断点或返回键困死 → 回改步骤表。
- 步骤3（五态、异常恢复与多输入）：异常无落点或五态缺 → 回补节点。
- 步骤4（数据、事件与交接）：下游需猜节点 ID → 回补命名。

下一步常接：`ux-review-pass`；`ui-logic-pass`；`ux-designer`；`copy-pass`。

## 工具锚

- UI 预制 / 蓝图路径（`Assets/` 或 `Content/`）
- 流程说明可用 `xmind` 或稿件 `.md`；交互状态表 `.xlsx`
- 真机截图落入 `.harness/artifacts/`

## 不在本文件

- 视觉终稿
- UI 逻辑代码
- 系统规则终裁
- Kit 组件像素稿
