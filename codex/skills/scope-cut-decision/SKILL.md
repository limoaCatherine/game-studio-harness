# 范围怎么裁

## 何时用

- 里程碑超容量要保日期，或功能膨胀偏离原计划
- 依赖断裂导致无法交付
- 需要可审计的裁剪记录，避免私下偷砍
- 体验批评队列溢出产能

## 怎么做

### 1. 对照原计划与现状

**做**
1. 打开里程碑看板（milestone board）导出原清单；列各项：已完成 / 进行中 / 未开始 / 新增未计划；标膨胀与阻塞来源；差额写入 `ScopeCut!A:F`（项/状态/证据贡献/扇出/沉没/初判）。
2. 写若不裁的后果：日期滑移、质量跌档、团队过载、活服空窗——用可观察描述，不写「会很惨」。
3. 标已沉没成本：进行中项再砍的浪费；但不因沉没成本自动保留（写清「留/砍」理由）。
4. 对照成功证据：哪些项真正服务证据，哪些是顺带做的「金镀」。
5. 收集下游依赖：砍 A 是否炸 B 的关键路径；扇出高的项单独标「炸弹」。
6. 向用户确认保序：日期 / 体验核 / 技术安全——不能全保时显式排序并记录。

**做到**：差额表（原清单 vs 现状）可见；不裁后果可观察描述；保序已定；扇出炸弹已标；失败→回本步 改 差额表或保序/炸弹标记

### 2. 评估裁剪候选

**做**
1. 每候选评：支柱对齐、依赖扇出、回补成本、玩家可感损失、对成功证据的贡献。
2. 至少给两套包：保体验核 / 保日期（可加「保技术安全」第三套）；附利弊请用户选。
3. 关键路径炸弹必须上台面进某套裁剪包。
4. 活服/活动项对照 `liveops-calendar`：挪期 vs 降强度 vs 砍；经济 Source 砍掉要写停发规则。
5. 叙事/关卡项：砍拍或降分支深度时回挂 `narrative-beat-sheet` / `quest-spec` 影响面。
6. 给出「降级占位」选项（灰盒代替、可跳过、数值占位、隐藏入口）及玩家可感损失说明。

**做到**：候选有评分列；≥2 套裁剪包可选；炸弹上台面；活服/叙事影响已写；失败→回步骤 1 改 炸弹清单或候选评分

### 3. 决策、去向与回补

**做**
1. 选定包后写移出项去向：下里程碑 / 砍掉 / 降级占位；每条通知下游 Owner 并要回执。
2. 更新成功证据与关键路径、DoD；残留风险挂 `risk-register-update`。
3. 写回补条件：何种信号/产能余量可捞回；无回补条件则标永久砍，避免幻想回潮。
4. 更新对外沟通点：商店页、预告、更新说明 stub、社区预期是否需改。
5. 冻结裁剪决议版本与日期；之后加回视同新变更，走里程碑变更规则。
6. 若产品表/开关：写下线或隐藏策略与责任人，避免「文档砍了客户端还入口」。

**做到**：移出项去向明确；DoD/关键路径已更新；回补条件在案；开关/隐藏策略齐；失败→回步骤 2 改 裁剪包或去向/回补条件

### 4. 执行核对与防偷加

**做**
1. 核对入口、任务、活动、商店、成就是否仍露出已砍内容；露出则关入口或改文案。
2. 核对关键路径是否变短且仍能到成功证据；不能到则裁剪失败，重开本流程。
3. 开一页「裁剪审计」落看板附件或 `ScopeCut_Audit` sheet：谁批、砍了什么、去向、回补条件、通知记录；与里程碑板 DoD 勾选同步。
4. 一周内复查偷加项；偷加视同变更违规，拉回决议或正式走加项裁换。
5. 与 `release-notes-stub` 同步：若玩家已知的预告被砍，写沟通口径（道歉/替代/延期）。
6. 站会置顶「本周裁剪未关闭项」直到入口与文档一致。

**做到**：无幽灵入口；审计可查；偷加被抓；路径仍达成功证据；失败→回步骤 3 改 开关/入口或重选裁剪包

下一步常接：更新 `milestone-plan` / `risk-register-update`；沟通 `release-notes-stub`。

## 工具锚

- 里程碑与范围裁切记录 `.md`
- 会话 `loadplan.json` / `activated.json` 与 `~/.cursor/skills` / `agents` / `mcp.json` 点名对照
- 发版说明与 `sync-state` 状态摘要路径
