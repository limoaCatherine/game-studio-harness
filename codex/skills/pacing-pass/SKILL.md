# 节奏怎么审与改

## 何时用

- 关卡/章节发闷或过载；休息点缺失、连战过长
- 叙事与战斗节拍打架；多遭遇串联后体验飘
- 活动一日程或赛季周节奏需要压力视图

## 怎么做

### 1. 锁时间轴与四层定义

1. 定范围：单关/章节/一日程/赛季周；单位统一为秒或统一节拍槽。
2. 叠四层：combat / info / narrative / reward；每层写「高」判据。
3. 收集输入 id：遭遇、beat、任务强制步、活动日历片段。
4. 确认休息定义档与支柱允许的高压形态。
5. 建轴表头：t_sec、seg_id、四层、rest?、notes；先占位后填实测。
6. 不合格：单位混用或输入缺 id → 统一并补命名。

**做到**：轴表单位固定；四层高判据可见；输入 id 齐全。

### 2. 秒表采样标异常

1. 按段走关记四层相对档与实际秒数。
2. 标异常：长真空、连续尖刺、信息过载、无休息、奖励空窗/过密、双高叠、教学落高压。
3. 每条异常挂钩 encounter/beat/quest_step + 时间码。
4. 对照支柱：该高压是否服务目标美学；支柱外「热闹」单列。
5. 对照试玩「累/闷」时间点；不对齐则加密采样。
6. 不合格：异常无法挂钩 id → 提高轴分辨率重采。

**做到**：异常表含 id+时间码+类型；双高叠/教学错位可标。

### 3. 改密度出回改订单

1. 每条异常给改法：砍支线几何/减波/插安全区/挪叙事拍/拆教学。
2. 回改订单字段：目标文件 id、改法、预期峰谷变化、Owner。
3. 连续高压超阈值必须插入喘息；过长优先砍可选而非砍主目标教学。
4. 与 liveops 日/周负担交叉时，标日历侧改法选项。
5. 禁止只改 BGM/特效冒充节奏修复。
6. 不合格：订单无 id 或无预期变化 → 回写清再派。

**做到**：回改订单含目标文件 id、改法、预期峰谷变化、Owner。

### 4. 回写、复测、冻版本

1. 改完复测原异常时间码；仍异常则升级改法强度。
2. 峰谷图与实测表入库；版本号与范围写头字段。
3. 交接关卡/叙事/活服各一页摘要。
4. 冻结本轮节奏包；大改开新版本。
5. 开放问题列制作方（支柱冲突高压等）。
6. 不合格：复测未闭合却冻版本 → 回步骤 3。

**做到**：原时间码复测闭合；峰谷图与 pacing_version 入库。

## 做到

- 轴表单位固定且四层高判据可见
- 异常表含 id+时间码+类型
- 回改订单已派并复测原时间码
- 峰谷图与版本号已入文档仓

## 失败回哪一步

- 步骤1（锁时间轴与四层定义）：单位混用或输入缺 id → 统一并补命名。
- 步骤2（秒表采样标异常）：异常无法挂钩 id → 提高轴分辨率重采。
- 步骤3（改密度出回改订单）：订单无 id 或无预期变化 → 回写清再派。
- 步骤4（回写、复测、冻版本）：复测未闭合却冻版本 → 回步骤 3。

下一步常接：`encounter-script`；`level-goals-spec`；`narrative-beat-sheet`；`level-designer`；`liveops-calendar`。

## 工具锚

- 节拍 / 对白稿 `.md` 与分支表 `.xlsx`
- 关卡或任务配置引用路径
- 评审记录写入 `.harness/artifacts/`

## 不在本文件

- 战斗数值主调
- 最终镜头动画
- 把观感当唯一证据无时间码
- 剪辑工程不当成本技能交付
