# 导出管线怎么验与修

## 何时用

- 导出器或插件改动后
- CI 导出红灯或静默成功
- 缺贴图仍 exit 0
- 同输入重跑产物不一致

## 怎么做

### 1. 备金样输入

1. 准备至少四类固定输入：标准好资源、缺贴图、坏命名、循环或断依赖；路径放在稳定金样目录，可一键指向。
2. 每例写期望：退出码、是否产出、日志必须含的关键句（路径+规则名/错误码）。
3. 好资源金样通过 `export-naming-gate` 规则；坏命名金样故意违反同一套 token，避免两套规则。
4. 记录金样的引擎/DCC 版本与导出插件版本；版本漂移时先更新金样说明再跑。
5. 向用户确认 CI 调用的同一命令行入口；本地与 CI 参数不一致先对齐。
6. 金样目录同时放好样本与坏样本；只有好样本时立刻补坏样。
7. 对照表（期望码 vs 实际码）只维护在金样目录旁一份，修管线后更新日期；后续步骤只更新该表勿复制粘贴。

**做到**：好坏四类金样可一键指向；期望 exit 码与关键日志句写清；CI 入口命令与本地一致。

### 2. 跑导出记码

1. 跑好样本：exit 0；产物清单（网格/动画/贴图）完整；抽查文件非空。
2. 跑缺贴图样：必须非 0；日志指出缺哪张路径；失败要红灯，不只打 warning。
3. 跑坏命名样：非 0；日志含期望模式或规则 id。
4. 跑断依赖/循环依赖样：非 0 或明确失败；半套产物不当成功。
5. 把实际码、关键日志行、产物列表贴进对照表；与期望逐行比。
6. 失败被吞成成功：修导出器错误处理（抛错/非 0），再重跑坏样直到红灯正确。

**做到**：对照表实际码=期望码；坏样非 0 且日志含路径；无 warning 假绿。

### 3. 查依赖与命名命中

1. 解析好样本产物的引用列表：贴图、材质、骨架、动画片段全部存在于约定目录。
2. 人为删一张依赖再导出：必须失败且指出路径；修到满足。
3. 对坏命名样确认命名规则命中（与 `export-naming-gate` 同一 token）；未命中则修规则接线，不是改金样名躲规则。
4. 检查日志噪音：无关 warning 淹没关键错误时，提升关键错误级别或前缀，保证可 grep。
5. 压缩/Draco 等选项：解码器缺失应显式失败；向用户确认项目是否启用该压缩。
6. 产物侧车清单（manifest）若有：校验清单与磁盘一致，防漏拷。

**做到**：好样本引用齐全；删依赖必失败指路径；坏命名命中同一 token；manifest=磁盘。

### 4. 幂等重跑

1. 同输入、同参数连跑两次；对产物树做 diff（或哈希）。
2. 仅允许已声明差异（如嵌入时间戳字段）；允许名单写进管线文档；名单外一律 FAIL。
3. 非幂等差常见源：随机临时名、未排序 JSON、绝对路径写入；修导出器去掉或规范化。
4. CI 复跑同一 commit 两次应对齐；不稳定则标管线债并修。
5. 修完后好坏样全量再跑一遍，更新对照表日期。
6. 打开两次产物目录并排比对文件数与关键体积，人工抽查无幽灵文件。

**做到**：同输入两次产物 diff/哈希仅允许名单内差异；名单外 FAIL 已修。

### 5. 接入 CI 与回归

1. 把好坏金样命令写进 CI 或本地一键脚本；参数与本地一致。
2. CI 红灯必须能点开日志看到路径+规则名；否则改日志格式。
3. 插件/导出器升级后强制重跑全套金样再合入。
4. 记录本轮修过的失败模式（吞错/非幂等/缺依赖）防回归。
5. 向用户确认金样目录是否进版本库；不进则写获取方式。
6. 打开最近一次 CI 产物对比本地，确认无环境差导致假绿。

**做到**：CI/一键脚本可复跑；插件升级强制全套金样；失败模式有记录；无环境差假绿。

## 做到

- 好坏金样均跑过且码符合期望；坏样本失败日志含路径与规则
- 无缺依赖仍成功；命名规则对坏样命中
- 同输入两次产物幂等（除声明差异）

## 失败回哪一步

- 金样只有好、期望码/日志句空、CI 入口不一致 → 回步骤 1
- 坏样 warning 假绿、实际码≠期望 → 回步骤 1 改期望或修错误处理后再跑步骤 2
- 删依赖仍成功、命名规则未命中 → 回步骤 2 修接线后再跑步骤 3
- 非幂等差在名单外 → 回步骤 3 去随机/绝对路径后重跑步骤 4
- CI 假绿、升级未跑金样 → 回步骤 4 修幂等/对照表后接入步骤 5

下一步常接：命名问题回流 `export-naming-gate`。
## 加厚：导出预设与批处理契约

### A. DCC 导出检查单（静态/蒙皮/动画分列）

1. 静态：选中渲染网格+碰撞；光滑组/法线按项目；应用缩放；不含灯光相机。
2. 蒙皮：网格+关节链根；保留蒙皮；影响数已剪裁；形态键勾选。
3. 动画：Bake 开；单动作导出；关键全骨骼；Root 骨运动策略与项目 Root Motion 一致。
4. 轴向前向：按目标引擎约定写进导出预设名（如「引擎A-角色」「引擎A-场景」）。
5. 文件落盘路径与 `export-naming-gate` 规则版本绑定；脚本导出带同一版本号元数据。

### B. 批处理与失败

1. dry-run 列表：将导出路径、预设名、依赖贴图是否拷贝。
2. 失败分类：命名拒、依赖缺、Bake 失败、轴测失败——失败不进待导入队列。
3. 成功清单交给 `import-validate`；两清单数量勾对。
4. 回归：改导出预设后抽 1 角色+1 场景+1 动画重跑。

**工具类别**：DCC 批导脚本、版本库、CI 导出任务、引擎导入机检。

## 工具锚点（live mcp.json）

- `meshlab` / `ffmpeg` / `imagemagick`：批处理夹具
- `docker-mcp`：隔离复现
- `gamedev-mcp`：编辑器导入复现
- `everything-search`：金样哈希定位
