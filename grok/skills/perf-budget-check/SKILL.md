# 性能预算怎么查与怎么改

实测对照预算、定位超项、给改法选项。**性能≠认证全文**：不写商店条款全文；认证性能抽检另走 `platform-cert-smoke` 短项。

## 何时用

- 对照帧时/内存/加载/DrawCall 预算验收
- 卡顿、掉帧、内存涨、加载过长需定位系统
- 优化前要排优先级，避免盲改

## 怎么做

### 1. 冻结场景、档位与预算数字

1. 向用户索取目标机帧时/内存/加载/DrawCall 等预算；无数字先问清再采。
2. 选定主城、常规战斗、最差关/人潮；记下设备档、构建 SHA、画质档。
3. 列出计数器：帧时 p50/p99、常驻内存、加载秒、DrawCall、GC 分配/帧。
4. 写固定操作脚本（路径+输入序列+时长），保证可复采。
5. 区分 CPU/GPU/IO 观察入口；检查预算与脚本已冻，否则停本步。

**做到**：预算数字与场景/档位/操作脚本冻结可复述。

### 2. 真机/目标档采样本

1. 在真机或目标档构建跑脚本；编辑器样仅对照。
2. 至少冷启首轮与热身再轮；导出 profiler 原始或摘要。
3. 尖峰帧绑定玩家操作（放技能/切场景/刷怪）与 Top Marker。
4. 内存记起止与峰值；标持续上涨 vs 平台锯齿；加载用日志时间戳对齐。
5. 检查两轮齐全且可复采；缺绑定操作则回本步。

**做到**：冷热样本可复采；尖峰有操作绑定。

### 3. 对照预算并分桶超项

1. 逐指标填预算、实测、状态（达标/告警/超标）；尖峰超标不可被平均值掩盖。
2. 分桶：CPU Tick、托管分配/GC、渲染、I/O、脚本逻辑。
3. 最差关与主城分别对照；按超出比例×可见频率粗排优先级。
4. 本查不偷偷改预算；改预算须另决策记录。
5. 检查超项列表可指到指标；不合格回本步。

**做到**：超项对照到指标状态与分桶。

### 4. 定位热点并给改法选项

1. 每超项下钻到模块/挂点/资产类型；出 Top3 热点表（位置、问题、影响、体量）。
2. 每热点给 2～3 选项（降频/池化/LOD/异步/砍内容/降默认档）写收益与风险。
3. 选定改后同场景同脚本同设备复测，写前后差；未达保留数据迭代下一热点。
4. 只拧画质滑杆不冒充代码优化完成；回流美术时指具体资产类型。
5. **不写商店认证条款全文**；认证性能抽检另走 `platform-cert-smoke` 短项，本文件与认证清单分流。

**做到**：热点到模块级；改法有选项；复测有前后数字差。

## 做到

- 预算数字与场景/档位/操作脚本冻结可复述
- 冷热样本可复采；超项对照到指标状态与分桶
- 热点到模块级；改法有选项；复测有前后数字差

## 工具锚

- profiler 导出、操作脚本、性能预算表
- 样本与对比写入 `.harness/artifacts/`
- `verify-report.json` 引用本批测量路径

## 失败回哪一步

- 预算空、脚本未冻 → 回步骤 1
- 缺冷热两轮、尖峰无操作绑定 → 回步骤 2
- 平均值掩盖尖峰、预算被偷改 → 回步骤 3
- 热点停在「整体慢」、无复测数字、只拧画质滑杆 → 回步骤 4

## 边界

- 不做：平台认证/商店条款全文与提审材料；功能用例 GWT 与回归包组包；机型兼容冒烟主责；Shader 规范终裁
- 与 `platform-cert-smoke`：本文件做预算实测；认证只做条款要求的性能短项，不在此扩写
- 与 `device-matrix-pass`：矩阵验档位可玩与降级；本文件做预算分桶与改法
