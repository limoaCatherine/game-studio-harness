# 服务端战斗权威怎么查

## 何时用

- 战斗不同步或客户端可改结算嫌疑
- 回放对不上
- 技能校验过松/过严
- 需要区分表现延迟与权威错误

## 怎么做

### 1. 划权威边界

1. 列必须由服务器裁定：命中、伤害、死亡、掉落、CD、控制命中。
2. 列允许客户端预测：表现、预输入、本地先行动画；写预测失败驳回/和解策略。
3. 灰区（位移、碰撞）写成明确归属：服务器校正频率 + 容忍距离；观战/录像是否走同一权威流写明。
4. 与 `client-combat-frame-debug` 分工：本流程调权威正确性；表现帧对齐不改权威数字。
5. 输出权威 vs 预测清单，评审一次冻结本里程碑。

**做到**：权威 vs 预测清单无灰色地带；位移有校正频率与容忍距离。

### 2. 查结算与随机

1. 核对结算输入：属性快照时机、随机种子来源（房间创建/回合开始/技能施放三选一写死）、技能 id、buff 列表；同种子应可回放。
2. `rg`/`Grep` 客户端上报伤害/击杀/CD 是否被服务器当最终值——有则记缺陷并开单。
3. 查数值范围、状态合法性（死不能放技能）、技能/移动包速率限制；零除/极值对照 damage-formula 钳制，服务端以自算结果为准。
4. 写一笔「同输入→同输出」验算用例（种子+快照）可自动或手工跑；属性快照与 damage-formula 快照规则交叉勾选。
5. 种子写入战报字段名写清，供事后复盘。

**做到**：结算可复现；无客户端终裁伤害路径，或已开单。

### 3. 驳回与取证

1. 抽测篡改伤害/CD/位置/技能 id/已下架技能：期望拒包或回滚；超速移动包期望拉回或拒。
2. 日志字段：玩家、技能、帧/时间、原因码、请求 id；驳回必须可追溯到这些字段。
3. 弱网下合法包重排：应和解而非误踢；与 `anti-cheat-hook-check` 误杀用例对齐。
4. 统计驳回原因码分布，找出过严码；把篡改用例脚本化进集成测或手工清单。

**做到**：篡改用例有拒绝证据；日志可追溯；弱网合法重排有和解结果。

### 4. 回放核对

1. 选关键战例：录服务器事件流与客户端表现时间线；缺回放工具时至少对比伤害序列、死亡帧数值日志。
2. 偏差分类：表现延迟（可接受）vs 权威错误（必修）vs 时钟漂移。
3. 权威错误开缺陷并挂回归，修复后附同种子回放对比；表现延迟交给 `client-combat-frame-debug`。
4. 表现延迟可接受上限（ms/帧）向用户索取；分类结果写入战例记录。

**做到**：偏差有分类；权威错误进缺陷并有同种子对比计划。

## 做到

- 权威边界清晰；结算输入可复现（含种子）
- 非法包可驳回且有日志；回放偏差已分类
- 无未处理的客户端终裁伤害

## 工具锚

- 战报 / 种子字段说明
- 非法包测日志与回放对比记录
- `.harness/artifacts/` 下本批证据

## 失败回哪一步

- 灰区未写归属、权威/预测清单有空洞 → 回步骤 1
- 种子来源未写死、发现客户端终裁伤害未开单 → 回步骤 2
- 篡改未拒、驳回无原因码、弱网误踢 → 回步骤 3
- 偏差未分类、权威错误无同种子对比 → 回步骤 4

下一步常接：`anti-cheat-hook-check`；表现帧 `client-combat-frame-debug`。
