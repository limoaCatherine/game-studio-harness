# 管线工具规格怎么写

## 何时用

- 新建导出/校验/转换 CLI
- 失败只打错误码、不可脚本化
- 要进 CI，需稳定退出码与金样
- 缺依赖被静默跳过要改成显式失败

## 怎么做

### 1. 定职责边界

1. 一句话职责；列出非目标（不做可视化编辑器、不做上传商店、不做权限系统等）。
2. 与相邻工具边界：输入输出谁消费；消费者工具名写清。
3. 成功长什么样：产物路径与校验通过条件；失败长什么样：退出码+人类可读修复建议。
4. Owner 与版本号策略（semver 或日版本）。
5. 在规格文首贴最小调用卡片：本地命令一行、CI 命令一行、期望 exit 码表链接。

**做到**：职责一句+非目标列表落盘；消费者可指；成功产物路径与校验条件可核。

**不合格**：职责/非目标空或消费者未指 → 回本步。

### 2. 冻 IO 与退出码

1. 写输入路径/格式、输出产物、日志流约定（机器可读 vs 人读）。
2. 退出码分类并保持稳定（如 0 成功、用法/数据/依赖/内部分码）；码表进帮助与文档双处。
3. 失败信息必须含：路径 + 命中规则 + 建议修复；成功时 exit=0。
4. 机器可读日志用 JSON 行或固定前缀，便于 CI grep。
5. 用一次故意坏输入跑通：捕获 exit 码写入 `tool_spec_smoke` 记录表；与帮助输出核对码表无漂移。

**做到**：退出码表进帮助与文档；同失败可脚本分支；失败含路径+规则+建议。

**不合格**：成功非 0 或同失败码漂移 → 回本步冻码表。

### 3. 配置与幂等

1. 列配置项与默认；优先级写死：CLI flag > env > 配置文件；给一条冲突示例证明 flag 胜出。
2. 临时目录用隔离目录并在异常路径清理；缺依赖显式失败（依赖码），不静默跳过。
3. 同输入连跑两次产物哈希一致（时间戳可归一）；并发输出隔离或文件锁策略写清。
4. 配置校验失败与内部错误分码，不混淆。

**做到**：连跑两次产物哈希一致；缺依赖显式失败非静默；并发策略可测。

**不合格**：缺依赖静默成功或连跑脏写 → 回本步修幂等。

### 4. 接测试钩

1. 准备金样：Happy、坏输入、缺依赖各至少一例；期望输出/退出码入库（金样目录）。
2. CI 钉扎工具版本或 commit SHA；金样更新须人工 diff 审批，CI 不自动覆写。
3. 最小测：Happy、坏输入、缺依赖；故意弄红能红。
4. 金样期望码与 smoke 记录对齐；漂移先改规格再改实现。

**做到**：金样与 CI 钩存在且故意弄红能红；版本钉扎可指。

**不合格**：无金样或 CI 覆写金样 → 回本步补钩。

## 做到

- 职责与非目标、消费者、成功产物路径可核
- 退出码稳定可脚本分支；失败含路径+规则+建议；幂等连跑哈希一致
- 金样与 CI 钩存在且故意弄红能红

## 工具锚

- 管线工具说明 `.md` 与脚本 `.py` / `.bat`
- `.harness/state.json`
- 导出修复日志写入 `.harness/artifacts/`

## 失败回哪一步

- 职责/非目标空、消费者未指 → 回步骤 1
- 退出码不稳、失败无路径、成功非 0 → 回步骤 2
- 连跑哈希漂、缺依赖静默 → 回步骤 3
- 金样缺、CI 覆写金样、期望码漂移 → 回步骤 4

下一步常接：`export-pipeline-fix` 验实现。
