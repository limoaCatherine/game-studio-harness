# 短文案怎么统一

## 何时用

- UI 字串术语不齐、截断或一行挤两义
- 物品/技能描述机械信息不清，风味盖住规则
- 语气与品牌或角色卡不符
- 术语与 naming 决议打架，或本地化键失控

## 怎么做

### 1. 收词与术语对齐（键表 + rg）

1. 导出待审键：打开项目字符串表 / 本地化导出 / 产品 strings sheet，列 `key|text|screen|type(btn/title/body/item/skill/sys)` 到 `copy/batch_<id>.csv`。
2. 对照 naming 决议与术语表；每行标 `canon|undef|conflict`；冲突只记账，本步不发明新名。
3. 拆机械 vs 风味：机械句必须含可核对条件/数值/消耗；风味不得改规则含义。
4. 同概念多名：定一个显示名，其余入 `deprecated→replacement`；在文案表、配表与 UI 资源中搜弃用显示名，列出残留键。
5. 可变数改占位符 `{item_name}`/`{count}`；会变的数字一律占位，不写死。
6. 向用户索取控件字符/宽度档与术语权威源；有档再比长短。

**做到**：csv 行数=待审键；canon/弃用可指；占位符覆盖全部可变值；无空档开工。

### 2. 按控件预算改写（计数器 + 实控件）

1. 按层改：标题/按钮/正文/脚注；用编辑器字符计数或脚本 `len(text)` 对照档；超长顺序：删从句→压同义→拆行——保持字号与间距，用字数解决超长。
2. 物品/技能描述统一顺序：效果→条件/消耗→风味；稀有度/绑定用语与项目表一致（打开物品 sheet.col 核对）。
3. 系统错误/确认：必须「发生了什么 + 玩家可做什么」；用可读句，不只甩内部错误码。
4. 同屏近邻 3～5 键并排：语气（敬语/命令/第二人称）与术语不得漂移。
5. 在真实控件或 Figma Auto-layout/线框宽度下目视：截断、换行炸、按钮溢出→回本步压字，不改布局冒充文案完。
6. HUD 短句用「动词+对象」；状态名对齐 `status-digest` 显示名，`rg` 对齐正式简称。

**做到**：抽样键 `len≤档`；控件预览无溢出；近邻语气一致；机械句无歧义。

### 3. 语气、敏感与付费句

1. 抽检敬语/命令式全库一致性；破格句改回或例外登记（键+批准人）。
2. 角色口吻短句对声线卡；破格标回 `dialogue-pass`，本步不重写长对白。
3. 敏感词表（向用户索取）扫 csv；命中改写并留 `was→now`。
4. 奖励/付费句：写清可选付费边界，主目标路径可免费完成；与 `event-spec` 伦理边界交叉检查。
5. 成就/邮件标题须说清触发方向；「悬疑到不懂为何收到」→重写。

**做到**：语气例外表可指；敏感命中=0 或已替换；付费句审查记录有日期。

### 4. 本地化风险与定稿

1. 标 L10n 风险：双关/谐音/文化梗/语序拼接/敬语依赖；风险键附「直译建议或勿直译」。
2. `rg` 弃用名：键表+任务文本+可见表残留必须清零或进替换包。
3. 定稿列：`key|final|mech/flavor|l10n_risk|source`；大面积改名回挂 `naming-consistency-check`。
4. 抽 10 条高曝光键（主界面/商店/战斗 HUD）做「一句说出规则」测试；说不清→回步骤 2 重写效果句。
5. 落表走表格写入配方（`excel-com-write`）；键名不随显示名改；冻 `copy_batch_version`。

**做到**：风险键列出；弃用残留=0 或替换包完整；定稿可交 L10n；版本可追溯。

## 做到

- 术语与 naming 一致；弃用有替换清单且残留清零
- 机械信息无歧义；风味不改规则；长度在控件档内；预览无溢出
- 占位符统一；付费/敏感已审；L10n 风险已标；高曝光键可一句说清规则

## 失败回哪一步

- conflict 未裁、档位空、占位未覆盖 → 回步骤 1
- 超长缩字号、机械句与表冲突、控件溢出 → 回步骤 1 修术语后回步骤 2 压字
- 付费暗示、敏感命中未改 → 回步骤 2/3 改完再进 L10n
- 高曝光键说不清、弃用残留>0 → 回步骤 3 清完再冻版本（步骤 4）

下一步常接：`naming-consistency-check`；长对白 `dialogue-pass`。

## 完成时必有

- 改前/改后对照表（句段 id 或路径）
- 禁改术语表已勾；未批术语不进正式稿
- 失败项标注回流：叙事 / UX / 程序本地化键
