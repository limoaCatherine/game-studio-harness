# 已批准事实怎么写入 canon

## 何时用

- 数值锚点、命名约定、接口真值等「稳定事实」已获批准
- 讨论档想法**不要**走本技能

## 怎么做

### 1. 准备候选

**做**
1. 写候选陈述原文（可验证的句子，避免形容词堆砌）。
2. 来源路径：会议纪要/变更单/用户确认记录；批准人与日期。
3. 适用范围：哪些系统/表/版本有效。
4. 讨论档、未获准草稿 → 排除。
5. 不合格：无批准人或无来源 → 停。

**做到**：候选含陈述、来源、批准、范围。

### 2. 对照冲突

**做**
1. 读现有 `.harness/memory/canon/` 条目；用检索键扫相关陈述。
2. 冲突则并列新旧，先请用户裁决，再写。
3. 替换旧条时：旧条标 `废弃`，留指针到新条。
4. 不合格：静默覆盖旧条 → 禁止。

**做到**：无未裁决冲突；废弃链可指。

### 3. 写入与登记

**做**
1. 路径：`.harness/memory/canon/`。
2. 条目字段：陈述、范围、来源、状态=`有效`、日期。
3. 用户确认后写入；`artifacts-append` 登记路径。
4. 回读新条，确认与候选一致。
5. 不合格：回读不一致 → 修正再回读。

**做到**：canon 中可见有效新条；索引已登记。

## 完成检查

- [ ] 候选有批准与来源
- [ ] 冲突已裁决
- [ ] 入库回读一致并已登记

## 工具锚

- `.harness/memory/canon/`
- 检索对照旧条
- `artifacts-append`

## 失败回哪一步

- 缺批准/来源 → 步骤 1
- 冲突未裁决 → 步骤 2
- 写入/回读失败 → 步骤 3
